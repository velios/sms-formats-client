# 01 — Дашборд: центрированная панель и жёсткая сетка строк

**Тип:** AFK · **Blocked by:** нет — можно начинать сразу

## Что построить

Перестроить дашборд (список PR) под макет `SMS Formats v2.dc.html` (секция `data-screen-label="Dashboard"`):

- Панель центрирована, `max-width: 1280px`, на всю доступную высоту.
- Поиск переезжает в шапку панели: строка 52px — заголовок «PULL REQUESTS» капсом, рядом счётчик-пилюля, справа поле поиска шириной 340px.
- Строки PR выровнены по жёсткой сетке `52px / minmax(0,1fr) / 280px / 116px`, разделитель `border-bottom`:
  - колонка 1: `#номер` (tabular-nums, приглушённый);
  - колонка 2: заголовок (ellipsis) + янтарная точка «есть несохранённые локальные правки» + ссылка ↗ на PR; под ним ветка моноширинным 12px;
  - колонка 3: лейблы-пилюли + чип автора, выравнивание вправо, переполнение клипается (`overflow:hidden`) — это осознанное решение;
  - колонка 4: бейджи `✓ N` (апрувы) и `✗ N` (ошибки валидатора, только если > 0).

Поведение не меняется: текущая сортировка (`sortPRs` уже совпадает с макетом), фильтрация по заголовку/ветке/номеру, клик по строке открывает workspace, ↗ не всплывает на строку.

## Критерии приёмки

- [ ] Панель дашборда центрирована (max 1280px), поиск — в шапке панели.
- [ ] Строки выровнены по сетке `52px / 1fr / 280px / 116px`, колонки совпадают с макетом.
- [ ] Сортировка, поиск и переходы работают как до изменения (существующие тесты зелёные).
- [ ] На ширинах 1280–1512 нет горизонтального скролла и «поплывших» колонок.
- [ ] Визуально соответствует Dashboard-экрану `v2.dc.html` (цвета/радиусы/отступы уже в токенах `styles.css`).
