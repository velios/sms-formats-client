# 02 — Воркспейс: единый хедер-бар и сетка «рабочая колонка + справочник»

**Тип:** AFK · **Blocked by:** нет — можно начинать сразу

## Что построить

Перестроить layout воркспейса банка под макет `SMS Formats v2.dc.html` (секция `data-screen-label="Workspace"`). Два связанных изменения одним слайсом, потому что хедер и сетка задают друг другу линии выравнивания.

### Единый хедер-бар (44px, на всю ширину)

Сейчас название банка живёт в сайдбаре, а тулбар файла — внутри редактора формата. Вместо этого один бар панельного стиля над всеми колонками:

1. **Зона банка** — ширина ровно `clamp(264px,19vw,340px) + gap`, чтобы разделитель после неё ложился на границу сайдбара: название банка (ellipsis) + ссылка ↗ на папку банка.
2. **Тумблер «Редактор / Итоговый файл»** — сегмент-переключатель; левая кромка совпадает с левой кромкой рабочей колонки. **Для `senders.txt` тумблер скрыт** (решение grilling-сессии: raw/structured-режима у senders не существует; в макете это не загейчено — гейтим мы).
3. **Имя файла** (моноширинный, ellipsis — единственный сжимаемый элемент бара) + ссылка ↗ + бейджи «Изменено»/«Удалён». Для senders — `senders.txt` + бейдж «Изменено».
4. **Текстовые кнопки действий** (по комментарию Лео — с подписями, не только иконки): ✎ Переименовать · ↶ Отменить · ↷ Повторить · | · ✕ Удалить · ⟲ Откатить. Гейтинг как сейчас: rename — только для локально созданных файлов; undo/redo по истории; delete недоступен для созданных; reset активен при изменениях. Разделители — вертикальные штрихи 1px.

### Сетка колонок

- Сайдбар: `clamp(264px,19vw,340px)` (вместо фиксированных 320px). Состав сайдбара не меняется (панель действий банка, панель файлов), только из него уезжает название банка.
- Рабочая колонка: поток сверху вниз «Регулярное выражение → Тестовая строка → Информация о совпадении»; «Информация о совпадении» растягивается до нижней кромки и скроллится внутри. Таблица групп получает полную ширину рабочей колонки.
- **Постоянная колонка справочника** справа: `clamp(320px,24vw,430px)`, на всю высоту, вкладки СНИППЕТЫ / ПОЯСНЕНИЕ / QUICK REF. Справочник больше не делит нижнюю половину с информацией о совпадении.
- Все зазоры 16px; верхние и нижние кромки панелей трёх колонок — на одних линиях; шапки панелей 40px капсом.
- Raw-режим («Итоговый файл») занимает рабочую колонку + колонку справочника (как в макете — одна панель на месте обеих).

### Что сохраняется (рамка «а» grilling-сессии — поведение не трогаем)

- CodeMirror-редактор и все контракты regex-lab: Recognition Progress (ADR-0007), Group selection (ADR-0010/0015), режим `\s+` (ADR-0012), Intersections (ADR-0011/0013).
- Связка «режим Группы → вкладка Сниппеты, режим Части → Пояснение»; в read-only вкладка Сниппеты скрыта (макет read-only не моделирует — правила текущие).
- Кнопка Approve, stale-session-предупреждение, статусы индексации, бейджи ошибок у действий банка — в макете отсутствуют, в приложении остаются; вписать их в новую сетку в текущем стиле.

## Критерии приёмки

- [ ] Хедер-бар собран по макету; разделитель зоны банка лежит на границе сайдбара; тумблер выровнен с рабочей колонкой.
- [ ] Для `senders.txt` тумблер скрыт, бар показывает `senders.txt` + бейдж «Изменено».
- [ ] При 1200px и длинном имени файла кнопки не сжимаются и не переносятся — сжимается имя (ellipsis).
- [ ] Гейтинг всех пяти кнопок действий идентичен текущему (rename только для созданных и т.д.).
- [ ] Три колонки стартуют под баром с одной линии и заканчиваются на одной нижней кромке; зазоры 16px.
- [ ] Справочник виден одновременно с редактором и таблицей групп на MacBook Pro 14 (1512px) без скролла страницы.
- [ ] Recognition Progress, group selection, `\s+`-режим, intersections-бейджи и scoped-вкладка работают как до изменения (существующие тесты зелёные).
- [ ] Approve, stale-предупреждение и статусы индексации видимы и не ломают сетку.
