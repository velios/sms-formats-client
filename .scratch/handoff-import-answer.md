## Правила работы

- `AGENTS.md`: разговор по-русски, минимализм, хирургические правки. Коммиты — английские, conventional (`feat(import-answer): …`), без `Co-Authored-By`.
- Каждый этап — своя ветка `feat/import-answer-*`, мерж в `main` по зелёным тестам (`bun run test`, линт), как это делалось у `prompt-package`. Этапы строго последовательны — каждый строится на предыдущем.
- **Тикеты не заводить**, PRD не редактировать. Находки и вынужденные отклонения от PRD — комментарием в issue #30.
- Чего не делать (вне объёма, уже решено): поддержка `<rename>` (узнаём → `unsupported-rename`, не применяем), терпимость к ```-ограждениям, проверка содержимого тел, починка бага #29 (`INVALID_REGEX` на `(?i)`), изменения в `prompt-package`, частичный/пофайловый импорт, новые ключи `localStorage`.

## Этап 1 — `feat/import-answer-core`: чистая сердцевина

Реализовать в `src/features/import-answer/core.ts` (форма — по образцу соседей `intersections`/`bank-inventory`/`prompt-package`):

- `parseAnswer(text) → ParsedAnswer` — построчная грамматика, зеркало печати пакета (`src/features/prompt-package/core.ts:109`): теги — строки целиком, тело между ними **байт в байт**, незнакомый тег — проза. Тип-контракт (размеченное объединение `broken | parsed`, `AnswerChange`, `AnswerProblem`, 7 видов проблем) — в ADR-0017 и в прототипе `parse-answer.ts`.
- Проверка границы `(bankPath, path)` — белый список двух форм (`<bankPath>/senders.txt`, `<bankPath>/formats/<имя>.txt`, имя без слэшей, символы §5 `src/content/format-rules.md`). Существующую `isBankFormatFilePath` **не** переиспользовать и не ослаблять — она мягче намеренно.
- Пост-классификация причины нарушения — отдельная функция, отдаёт код (не строку): «другой банк», «в корне только senders.txt», «путь наружу», иначе «недопустимый путь». Тексты для человека — не здесь (i18n, этап 3).

Тесты (без сети, без рендера; удобен `/tdd` — красные тесты пишутся прямо из контракта):

- круговая проверка «печать пакета → разбор → тела байт в байт», включая хвостовой перевод строки и `<file path="…">`-строку внутри тела;
- синтетика на все 7 видов проблем; деление на «блок не доехал → broken» и «доехал, но…»;
- порядок применения = порядок ответа, побеждает последний блок по пути;
- прогон трёх ответов корпуса: ноль проблем, ожидаемые составы; ответ `amex` — `parsed` с пустым `changes`;
- граница: обе формы проходят; `..`, чужой банк, подпапка в `formats/`, не-`.txt`, пустой путь — нет.

## Этап 2 — `feat/import-answer-hook`: данные и запись

Реализовать `useImportAnswer` (`use-import-answer.ts`):

- **Добыча действующих тел** затронутых путей до показа: черновик — бесплатно (`DraftEntry.content`), остальное — head-ref через существующие `fetchFileContent` / кэш тел. Ошибка загрузки → частичного показа нет: состояние «ошибка + Повторить», импорт недоступен.
- **Запись** — цикл в порядке ответа: `write` → `setDraft(path, content, baseSha, remoteContent)` (`baseSha` из дерева source, `remoteContent` — добытое действующее тело), `delete` → `markDeleted`. Никаких новых методов стора. После записи undo и `resetFileToRemote` должны работать как на ручной правке — покрыть тестом.
- **Перезапись ручной правки** — признак строки: по пути из ответа существует черновик. Отдаётся наверх для значка и счётчика.
- **Пересчёт пересечений** — по флагу зовётся существующий `useIntersections.calculate()`; результат («пересчитаны / нет») — в сводку.
- Липкого состояния нет: ни текст, ни галочка ничего не пишут в `localStorage`.

Тесты — на хук с фейковым стором (образец — `use-prompt-package.test.tsx`): запись в порядке ответа, победа последнего дубля, поведение при ошибке добычи, undo после импорта.
