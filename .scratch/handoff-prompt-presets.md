## Задача 1 — пресеты задач в модалке «AI промпт»

**Не отдельная кнопка.** В модалке `PromptPackageModal.tsx` над/рядом с полем задачи — выбор из дефолтных промтов (меню или компактные чипы), выбор **подставляет текст в поле задачи**, поле остаётся полностью редактируемым. Подстановка перетирает текущий текст поля (это дефолтная заготовка, а не слияние). Тексты — в i18n (`src/i18n/ru.json` / `en.json`, узел `promptPackage`).

Два пресета:

**«Починить изменённые файлы»** — сценарий: в PR добавлены/отредактированы файлы (слои `pr` и `draft`), они не проходят проверки. Чинить только их, приводя к совместимости со всеми остальными форматами банка; нетронутые файлы банка не менять без необходимости. Текст (черновик, НЕ проверен живым тестом — прогнать по той же методике при желании):

> Почини файлы, изменённые или добавленные в этом pull request (слои `pr` и `draft`): устрани всё, что перечислено в блоке `intersections`, и сделай их совместимыми с остальными форматами банка. Файлы, не тронутые в этом PR, не меняй — кроме случая, когда без правки соседа пересечение не устранить; такой случай объясни в прозе. Якоря бери только из реальных текстов EXAMPLE. Перед выдачей проверь: каждый пример матчится своим regex, ни один пример не матчится regex другого формата банка, число capture-групп равно числу колонок.

**«Привести банк в порядок»** — полный проход по всем файлам банка. Текст — из `<task>` в `package-with-tested-task.txt`, проверен живым тестом; структура несущая, не упрощать:

1. починить всё из `intersections` (пересечения + example_no_match);
2. переписать легаси на современный стандарт (дефолтные сниппеты каталога как есть, `date#dd.MM.yyyy` → `date#dMy`; информационные форматы не переводить на транзакционные правила);
3. убрать избыточность: одинаковые `COLUMNS` + один шаблон → объединять, лишний файл — блоком `<delete>` с причиной; **ни один пример не теряется — примеры удаляемого файла переносятся в консолидирующий**; разный набор сущностей → не сливать, разводить негативным lookahead (cookbook §5);
4. якоря только из EXAMPLE, не хардкодить переменные части (URL, хвосты);
5. самопроверка итогового состояния банка целиком (ответ поверх слоёв, все пары форматов);
6. проза-отчёт: что объединил, что удалил, что оставил и почему.

В пункт 3 проверенного текста добавь фразу про перенос примеров (выделена жирным выше) — в прогнанном варианте её не было, агент перенёс примеры сам, но правило должно быть явным.

Плейсхолдер поля задачи (`promptPackage.taskPlaceholder`) обнови: сейчас «Что сделать с форматами этого банка» — добавить намёк «какие файлы, что сделать, можно ли удалять/объединять».

Тесты: пресет подставляет текст в поле; поле редактируемо после подстановки; собранный пакет содержит текст поля (существующие тесты `core.test.ts` / `use-prompt-package` — образец).

## Задача 2 — правки легенды (`LEGEND_TEMPLATE`, `src/features/prompt-package/core.ts:73`)

Три добавления:

1. **Приоритет:** прямые указания из блока `task` имеют приоритет над правилами этой легенды.
2. **Консолидация:** если задача явно разрешает массовую переделку, дубли убираются объединением форматов: примеры удаляемого файла **все до одного** переносятся в консолидирующий файл, удаляемый оформляется блоком `<delete>` с причиной. Ни один EXAMPLE не должен пропасть из банка.
3. **Проза всегда:** перед блоками — краткий отчёт, что сделано и чего агент делать не стал и почему.

Легенда — часть контракта пакета: в `core.test.ts` она зафиксирована дословно (`LEGEND_VERBATIM`, строка ~9) — обнови вместе с шаблоном. Помни правило работы с ним: агент читает легенду как единственную инструкцию — формулировки короткие, в стиле существующих абзацев.

## Задача 3 — правки контент-доков (`src/content/`)

Файлы `cookbook.md` и `format-rules.md`; `*.generated.ts` пересоздаются автоматически (`content:build` в pre-хуках dev/test/build), руками не трогать. Упстрим-доки не трогаем (правила задаёт zenmoney/sms-formats; это правки только наших справок).

1. **Расхождение `\b`/`\w` браузер ↔ Python.** В JS-движке без флага `u` `\b` и `\w` — ASCII-only, в Python `re` — юникодные. Следствие: паттерн с `Код\b` или `\w` рядом с кириллицей проходит CI апстрима, но в нашем редакторе даёт `EXAMPLE_NO_MATCH`. Именно это — корень всех четырёх example_no_match теста АТБ (форматы 3870, 9190, 11599, 11748). Куда писать:
   - `format-rules.md`, раздел «Где наше приложение мягче» — добавить как четвёртое расхождение (здесь редактор **строже**, зеркальный случай к `(?i)`);
   - `cookbook.md` §1 — утверждение «`\w` матчит кириллицу без флага `u`» снабдить оговоркой про браузерный движок; рекомендация: рядом с кириллицей вместо `\b`/`\w` — литеральные якоря или явные классы.
2. **URL и переменные хвосты не якорить.** В `cookbook.md` §4 («Якоря — только реальные токены SMS») добавить: URL с путём/параметрами, идентификаторы сессий и прочие переменные хвосты — не якоря; якорить только стабильную часть, хвост не включать в паттерн вовсе (поиск подстрочный). Антипример из теста: `https://link\.atb\.su/history` целиком в паттерне.
3. Проверь, не дублирует ли §2/§6 новые пункты — если формулировка ложится в существующую таблицу/список, расширяй их, а не заводи новые разделы.
