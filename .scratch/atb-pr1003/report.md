## Что сделал агент

Один блок `<file>` — только PR-файл. Больше ничего.

```
было:  Перевод\s+(.+?)\s+Списано\s+(\d[\d\s.,]*)\s+([^\s║]+)(?:\s+║\s+.+)?
стало: (?<!СБП:\s)Перевод\s+(.+?)\s+Списано\s+(\d[\d\s.,]*)\s+(\S+)
```

1. Пересечение с `СБП Перевод Ольга Валентиновна К Списано р_11408.txt` снято негативным
   **lookbehind** `(?<!СБП:\s)`.
2. `instrument`: `([^\s║]+)` → дефолт каталога `(\S+)`.
3. Опциональный хвост `(?:\s+║\s+.+)?` удалён целиком.

Прозой перед блоками — разбор каждого решения и отдельный раздел «чего делать не стал».

## Критерии handoff'а

- **Валидация чистая** — да (по апстрим-движку), см. таблицу.
- **Ни один EXAMPLE не пропал** — да.
- **Минимальность** — идеальная: тронут ровно один файл, PR-овский. Диффов по остальным
  32 форматам банка нет. `_11408` не тронут.
- **Дефолты** — `(\S+)` для валюты, `\s+` в склейках, опциональная группа убрана; каждое
  решение объяснено прозой.
- **Проза перед блоками** — есть, с разделом «чего не стал и почему».
- **Ожидаемый исход (слияние с `_11408` либо прозаическое обоснование, почему нельзя)** —
  агент выбрал вторую ветку: не слил, обосновал прозой, зафиксировал пару как кандидата
  на комплексную проработку.

## Расхождения с ожиданиями — что записать на будущее

Правки контент-доков в этот прогон не входят (по правилам handoff'а). Ниже — фактура для
отдельной задачи.

### 1. Точечный пресет систематически предпочитает разведение слиянию

Handoff ожидал переноса примера в `_11408` и `<delete>` PR-файла. Пресет `fixChanged`
этого не допускает: «Файлы, не тронутые в этом PR, не меняй — кроме случая, когда без
правки соседа пересечение не устранить». Разведение — это правка **только своей**
стороны, поэтому исключение не наступает, и минимальность побеждает cookbook §5
(«совпали истинные наборы — не разводи, а объединяй»). Агент увидел оба правила, назвал
конфликт вслух и разрешил его в пользу задачи — по букве пакета верно.

Вопрос к формулировке: должен ли точечный режим уметь сливать формат PR с соседом, когда
наборы сущностей совпали, или это сознательно оставлено комплексному режиму. Сейчас
пакет отвечает «оставлено комплексному», и это нигде не сказано явно — вывод получается
из двух правил в разных блоках.

### 2. Разведение lookbehind'ом здесь объективно слабее слияния

Проверено:

```
"СБП: Перевод Ольга Валентиновна К. Списано 10000 р."   → PR-regex не ловит (ок)
"СБП:  Перевод Ольга Валентиновна К. Списано 10000 р."  → PR-regex ЛОВИТ
```

Один лишний пробел после `СБП:` — и пересечение возвращается, причём `_11408` такую SMS
тоже ловит (у него `СБП:\s+`). То есть фиксированная ширина lookbehind'а делает
дискриминатор хрупким ровно там, где остальной паттерн терпим к пробелам. Слияние двух
форматов от этого класса регрессий иммунно.

### 3. Cookbook знает только lookahead

`cookbook.md` §5 называет штатным приёмом разведения негативный **lookahead**; lookbehind
упомянут лишь в `format-rules.md` §2 в перечне конструкций, не влияющих на нумерацию
групп. Здесь маркер чужого формата (`СБП:`) стоит **слева** от точки старта матча, и
передний lookahead до него не дотягивается — агенту пришлось вывести зеркальную форму
самостоятельно. Если разведение префиксом остаётся легальным приёмом, §5 стоит про этот
случай сказать (и заодно про фиксированную ширину lookbehind в Python `re`); если нет —
сказать, что префиксный маркер разведением не лечится, лечится слиянием.

### 4. `intersections` подсовывает точечному режиму чужие файлы

Пресет требует «устрани всё, что перечислено в блоке `intersections`», а блок содержит
два `example_no_match` из файлов, которых PR не касался, и оба — артефакт браузерного
`\w`. Агент устоял, но формулировка прямо толкает лезть в нетронутые файлы ради
расхождения движков. Кандидаты: сузить требование до пересечений с участием изменённых
файлов, либо помечать в блоке строки, объяснимые расхождением движков.

## Правки по итогам прогона и повторный прогон

Все три расхождения закрыты правками в тексте (кода не трогали):

- пресет `fixChanged` — второе исключение из «нетронутые файлы не меняй», прямо
  разрешающее слияние с соседом при совпавшем шаблоне и наборе сущностей; требование по
  `intersections` сужено до «что относится к изменённым файлам»;
- шапка блока `intersections` — предупреждение про ASCII-`\w`/`\W`/`\b` в браузере
  против юникодных в Python `re`;
- `cookbook.md` §5 — абзац «маркер перед началом матча — признак слияния, а не
  разведения».
