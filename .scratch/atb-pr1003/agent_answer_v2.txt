В PR затронут ровно один файл — `src/АТБ-ru_4679/formats/Перевод Юлия Дмитриевна В Списано р СБП.txt` (слой `pr`; слоя `draft` в пакете нет). На него в блоке `intersections` приходится одно пересечение: его regex распознаёт пример соседнего формата `СБП Перевод Ольга Валентиновна К Списано р_11408.txt` — «СБП: Перевод Ольга Валентиновна К. Списано 10000 р.».

Разводить эту пару нечем. Оба SMS — один и тот же шаблон «Перевод <получатель> Списано <сумма> <валюта>» с одним и тем же набором сущностей (payee, outcome, instrument) и одинаковыми COLUMNS; различаются они только тем, где записана метка канала «СБП»: в одном она стоит впереди («СБП: Перевод …»), в другом — в хвосте («… ║ СБП»). Это ровно случай из cookbook §5 «Маркер перед началом матча — признак слияния, а не разведения»: передний негативный lookahead метку впереди не видит (от стартовой позиции матча он смотрит только вперёд), а зеркальный lookbehind в Python `re` фиксированной ширины и разваливается на вариативных пробелах. Поэтому я воспользовался вторым разрешённым в задаче случаем правки нетронутого соседа — объединением.

Что сделал:

1. Объединил оба формата в уже существующий файл `СБП Перевод Ольга Валентиновна К Списано р_11408.txt` — он остаётся, потому что у него есть id (11408), уникальный внутри банка, а файл из PR заведён без id; имя файла при этом остаётся корректным, так как первый пример в нём не меняется и вычисляемое из него имя совпадает с текущим. Пример из PR перенесён в этот файл вторым примером — ни один EXAMPLE не потерян.
2. Regex остающегося файла: снял префикс `СБП:\s+`, из-за которого формат не ловил вариант с меткой в хвосте. Остальное — уже дефолты каталога и я их не трогал: payee `(.+?)` (§3.6, ограничен справа реальным якорем `Списано`), сумма `(\d[\d\s.,]*)` (§3.1, копейки в примерах то есть — «10000» без копеек, «500» без копеек), валюта `(\S+)` (§3.3, токен «р.» ограничен пробелом), склейки `\s+` (пробелы в обоих примерах есть всегда). Ни `^`, ни хвостового `.*`, ни опциональных групп. Итоговый паттерн: `Перевод\s+(.+?)\s+Списано\s+(\d[\d\s.,]*)\s+(\S+)`.
3. Файл из PR удалил блоком `<delete>`: после переноса примера он полностью дублирует остающийся формат.

Из паттерна PR-файла при переносе ушли две вещи, обе — как недефолтные без триггера: `([^\s║]+)` заменено на дефолт валюты `(\S+)` (в примере «р.» и так отделён пробелом от `║`, исключать символ незачем — cookbook §3.3, антипаттерн 14) и выброшен хвостовой `(?:\s+║\s+.+)?` — опциональная конструкция без наблюдаемой вариации и по сути хвостовой `.*` (§4, антипаттерны 10, 11). Метка `║ СБП` в паттерн не берётся вовсе: поиск подстрочный, хвост можно просто не описывать.

Чего делать не стал:

- Не трогал два `example_no_match` из блока `intersections` — `Карта Оплата услуг МТС RUR Доступно RUR_3870.txt` и `Оплата р Карта https link atb su history_9190.txt`. Эти файлы в PR не менялись, к правкам PR отношения не имеют, а сами «непопадания» — артефакт браузерного движка: в обоих паттернах `\w` стоит рядом с кириллицей («плата ус\w+» → «услуг», «[Оо]плат\w*» → «Оплата»), а в браузере `\w` всегда ASCII. В апстримном Python `re` эти примеры матчатся, файлы корректны (format-rules, «Где наше приложение мягче», п. 4).
- Массовую переделку легаси-форматов банка (там повсеместно `^`, end-anchored `([\d\s.,]*\d)`, `date#dd.MM.yyyy`) не делал — задача этого явно не просила.
