# Оформление интерфейса

При изменении оформления сохраняйте состав элементов, надписи и порядок расположения. Значительные изменения структуры экрана сначала согласуйте.

Источник токенов и общих классов — [src/styles.css](../src/styles.css), размеры и состояния контролов — [src/components/ui/](../src/components/ui/). Сверяйте изменения с этими файлами; новые экраны собирайте из существующих частей.

| Часть интерфейса | Правило |
| --- | --- |
| Корневой шрифт | 16px: стандартный шаг Tailwind равен 4px |
| Рабочий текст, regex и тестовая строка | `text-sm`, 14px |
| Файлы, сниппеты, пояснения и подписи | `text-xs`, 12px; справочный текст с интервалом 18px |
| Внешнее поле, промежутки между панелями, поле панели | 12px |
| Поле карточки, расстояние между контролами | 8px |
| Расстояние между тесно связанными элементами | 4px |
| Строка списка файлов | 28px |
| Заголовок панели | минимум 36px; при нехватке ширины переносится |
| Панель банка | 44px |
| Кнопки и поля | обычные 32px, компактные кнопки 28px; длинные подписи могут переноситься |
| Скругления | 4px у контролов и карточек, 8px у панелей; фильтры могут иметь форму капсулы |

Используйте общие классы `ui-panel`, `ui-panel-heading`, `ui-panel-body`, `ui-panel-inset`, `ui-panel-stack`, `ui-tabs`, `ui-tab`, `ui-list-row` и `ui-card`. Активная вкладка задаётся через `data-active`. Эти классы отвечают за оформление; размеры колонок, прокрутку и расположение содержания задаёт экран. Промежутки между колонками и вертикальными панелями берутся из `--panel-gap`.

Цвета выбираются по назначению: `background`, `card`, `muted`, `accent`, `foreground`, `muted-foreground`, `border`, `primary`, `success`, `warning`, `destructive` и их мягкие фоны. Новые оттенки и произвольные размеры добавляются только при конкретной необходимости. Используйте один sans-шрифт и один mono-шрифт. Декоративные тени не нужны; тень остаётся у диалогов и всплывающих элементов.

Палитра групп захвата и частей regex остаётся отдельной: её цвета передают смысл. Общая форма токенов задаётся классом `regex-token`, таблицы типов задают только цвета. Исключения для подсветки и геометрии редактора не меняют правила оформления обычных контролов.

## Сборка панели

```tsx
<div className="ui-panel flex min-h-0 flex-col">
  <div className="ui-panel-heading">
    <span>{title}</span>
    <Button size="sm" onClick={onAction}>{actionLabel}</Button>
  </div>
  <div className="ui-panel-body min-h-0 flex-1 overflow-auto">
    {children}
  </div>
</div>
```

Используйте `variant` и `size` существующих контролов вместо повторения их оформления на экране. В `className` экрана задавайте его геометрию: ширину, рост, прокрутку и расположение. Повторяющееся оформление исправляйте в общем классе или компоненте, чтобы следующий экран получал те же правила.

Заголовок с названием и действиями использует `ui-panel-heading`. Для заголовка с вкладками задайте `data-variant="tabs"`, а внутри разместите `ui-tabs`: вариант сам задаёт отступы, ширину вкладок и единственную нижнюю границу. Обычный ряд вкладок под заголовком использует `ui-tabs` самостоятельно.

Горизонтальные поля заголовков и содержания используют один `--panel-gap`. Для собственной панели инструментов или строки списка применяйте `ui-panel-inset`: он задаёт только горизонтальные поля, сохраняя высоту и вертикальные отступы экрана. Состояния загрузки, ошибки и пустого списка внутри панели используют `ui-panel-body`, чтобы их содержимое совпадало с заголовком по краям.

## Поля и действия диалога

Связку подписи, контрола и пояснения собирайте через `ui-field`; оформление подписи и пояснения задают `ui-field-label` и `ui-field-hint`. Связывайте подпись с контролом через `htmlFor`/`id`, пояснение — через `aria-describedby`, когда оно относится к полю.

```tsx
<div className="ui-field">
  <label className="ui-field-label" htmlFor={inputId}>{label}</label>
  <Input aria-describedby={hintId} id={inputId} />
  <p className="ui-field-hint" id={hintId}>{hint}</p>
</div>
<div className="ui-dialog-actions justify-end">
  <Button onClick={onCancel}>{cancelLabel}</Button>
  <Button onClick={onSubmit} variant="primary">{submitLabel}</Button>
</div>
```

`ui-dialog-actions` задаёт расстояния и выравнивание элементов внутри ряда. Выравнивание ряда по правому краю и верхняя граница остаются на экране. Общий диалог задаёт поля и расстояния между заголовком, содержанием и действиями по 12px; дополнительные внешние отступы у этих частей не нужны. Строки checkbox и составные селекторы сохраняют собственную структуру.

## Слои тестовой строки

`MatchOverlayTextarea` применяет `sms-text-layer` к текстовому полю и слою подсветки. Этот класс задаёт общую геометрию текста: шрифт, интервал строк, отступы, переносы, табуляцию и минимальную высоту. Изменяйте их вместе в общем классе; положение слоёв, прозрачность и обработка прокрутки остаются в компоненте.

## Состояния и переключатели

Загрузка, пустой результат и ошибка используют тот же контейнер и горизонтальное поле, что и обычное содержание. В списке применяйте `ui-panel-body` к состоянию без строк; у строк и поисковой панели используйте `ui-panel-inset`. Если внешний контейнер уже задаёт поле, не добавляйте его повторно. `ui-state` задаёт ряд текста и индикатора загрузки без собственного поля.

Текстовые уведомления собираются через `ui-notice`: поле 8px, шрифт 12px, интервал 18px, общее скругление и граница. `data-tone="error"` и `data-tone="warning"` задают семантические цвета; отсутствие тона — нейтральное сообщение. Расположение текста, кнопок и списков внутри уведомления задаёт вызывающий экран. Короткие метки состояния и счётчики сохраняют `StatusBadge`.

Переключатели режима «Редактор / Итоговый файл» и «Группы / Части» используют `ui-segmented` и кнопки `ui-segment`. Активность задаётся нативным `aria-pressed`, активный сегмент имеет синий фон. Вкладки содержимого используют `ui-tabs` и `ui-tab`: их нижняя линия отличает навигацию между разделами от переключения режима.

Фиксированные высоты строк применяются к кратким спискам файлов; длинные описания и сообщения могут переноситься и увеличивать высоту. Размеры рабочих областей, прокрутка, палитры подсветки regex и структурного diff, а также оформление длинных Markdown-документов остаются специализированными. Они не требуют отдельного словаря для обычных панелей и состояний.
