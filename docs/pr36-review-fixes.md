# Исправления замечаний к PR #36

Проверка от 30 сентября 2026 года по `/tmp/pr36-review.md`, составленному для `697b7e0`. Все шесть функциональных дефектов и дублирование цветов подтверждены и исправлены в той же ветке PR.

| Замечание | Исправление | Проверка |
| --- | --- | --- |
| F1: потеря переноса строки примера и пробела regex | Парсер убирает только один разделитель секции или завершающий перенос файла. Значимые пробелы и крайние переносы тела сохраняются. Загрузчик банка и живой снимок пересечений также сохраняют regex | Последовательный ввод `A` → `A\n` → `A\nB`, regex `A `, roundtrip пустых и многострочных примеров; ввод клавишами в Chrome |
| F2: удаление/переименование нового файла во время записи | Отсутствующий захваченный документ после успешной записи становится черновиком удаления уже опубликованного пути. Новый путь переименования остаётся созданием. Откат существующего документа восстанавливает его прежнее тело поверх опубликованного | Удаление, переименование, переключение области PR, повторная загрузка сохранённых черновиков, откат существующего файла |
| F3: пакет смешивает текущий main с head PR | `baseSha` сессии определяется через общий коммит веток (`merge base`). Разреженный слой PR и состав базового слоя теперь относятся к одной базе. Контракт пакета явно называется `baseSha` / `headSha` | REST-адаптер закрепляет общий коммит, включая публикацию с override SHA; пакет сохраняет пересечение неизменённого файла с изменённым, когда main уже ушёл вперёд |
| F4: поиск использует предыдущий head | Производный индекс связан с репозиторием, SHA и банком. Новая ревизия сразу исключает старые записи и запускает переиндексацию; завершение старого запроса не меняет индекс или счётчики новой ревизии | Тот же путь с `alpha` в старом head и `beta` в новом; старый запрос завершается во время новой загрузки |
| F5: пустой REST-файл считается ошибкой | Проверяется тип `content`, поэтому пустая строка возвращается как документ, а отсутствующее или некорректное поле отклоняется | Пустое тело и три некорректных ответа REST |
| F6: undo/redo обходит режим чтения | Все команды истории в FormatEditor проверяют общий запрет изменений. Отправители также проверяют `readOnly` перед вызовом истории | Переход редактируемого документа в режим чтения, undo и redo в текстовом и структурном представлениях; отправители; режим чтения в Chrome |
| S1: две таблицы цветов токенов | CodeMirror использует существующую `getRegexTokenClass` из единственной таблицы оформления | Сборка и визуальная проверка редактора |

Из рекомендаций по структуре убран промежуточный хук публикации и повторная передача наборов изменений: preflight работает с захваченным набором документов. Общая операция проверки банка используется публикацией и окном валидации; состояние отправителей захватывается до ожидания сети. Уточнены имена SHA и исходных head-тел черновиков, модуль approve переименован в `use-pull-request-approval`, представления импорта — в `AnswerImportViews`, построение колонок — в `buildColumnsForGroupCount`. Тип сессии берётся непосредственно из предметной модели. Добавлены короткие пояснения ограничений из review.

Рекомендация собрать весь жизненный цикл сессии в одном модуле остаётся отдельной структурной доработкой. Эта проверка исправляет подтверждённые дефекты и локальное дублирование; перенос открытия и фонового обновления целиком не выполнялся.

`bun run verify` проходит: typecheck, 512 тестов в 64 файлах, проверка секретов и линтер. Проходят сборка SPA, Linux-бинарника и семь сценариев локального roundtrip бота. В Chrome проверены сохранение пробела regex, ввод второй строки SMS, текстовая проекция и команды истории в режиме чтения. Скриншоты просмотрены; ошибок приложения в проверяемых сценариях нет. При первом открытии dev-сервера браузер отдельно сообщил об отсутствующем `favicon.ico`.

GitHub Compare API проверен чтением по реальным commit SHA. Запись пользовательских форматов, Telegram и deploy не выполнялись. Архитектурный контракт обновлён в [ADR-0018](adr/0018-coherent-revisions-and-publishing.md), актуальные измерения — в [отчёте реализации аудита](audit-implementation.md).
