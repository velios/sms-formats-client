# Координация имплементации: пакет промта

Фронт для агента-координатора. Ты **не пишешь код сам** — режешь работу на подзадачи, запускаешь саб-агентов, принимаешь их работу по воротам и держишь порядок. Пишешь руками только склейку и `CONTEXT.md`.

## Что читаешь сам, до первого саб-агента

1. **PRD** — `gh issue view 20` (issue #20). Требования и поведение.
2. **ADR-0016** — `docs/adr/0016-prompt-package-deep-module.md`. Форма кода и границы модулей.
3. `AGENTS.md` — как себя ведёт исполнитель (минимализм, хирургические правки, не трогать соседнее).
4. `CONTEXT.md` — язык домена. Термины из него не переизобретать.
5. `docs/adr/0009-*` (контент-пайплайн) и `docs/adr/0014-*` (дисциплина выборок инвентаря) — их правила действуют на W2 и W4.

Резолюции карты (#11–#19, карта закрыта) читай **только** если всплывёт «а почему именно так»: всё, что из них следует, уже перенесено в PRD и ADR.


## W1 — написать `src/content/format-rules.md`

**Бриф саб-агенту.** Написать человекочитаемый документ `src/content/format-rules.md`, описывающий контракт формата файлов апстрима `zenmoney/sms-formats`. Материал — `docs/research/format-rules-inventory.md` из ветки `research/format-rules-inventory` (42 правила с источниками `файл:строка`) плюс раздел «Новый документ `format-rules.md`» в PRD #20, где перечислены факты, обязательные к попаданию. Рамка документа — контракт **апстрима**, а не поведение нашего редактора, плюс отдельный финальный раздел «где наше приложение мягче» ровно из трёх пунктов (перечислены в PRD). Локальный клон апстрима для сверки — `/Users/flocktory/Code/2_zen/tools/sms-formats`.

**Граница с cookbook** — применяй к каждому правилу как тест: *если правило можно проверить, не разбирая семантику regex, — оно в `format-rules.md`*. Разбираешь семантику паттерна — это cookbook, не дублируем. Единственная зона нахлёста — колонки: cookbook даёт их как сущности, мы даём как контракт файла.

**Отдельное правило, которое обязано попасть в документ дословно по смыслу — `balance` против `av_balance`.** Обе колонки легальны и обе денежные, выбор определяется текстом SMS, но дефолт асимметричный: по умолчанию ставится **`av_balance`** (доступная сумма, обычно остаток плюс кредитный лимит, метка «Доступно» / `Available` — 3600 файлов корпуса против 364); **`balance` ставится только при веском основании, и основание проговаривается** — SMS сообщает фактический остаток («Баланс», «Остаток», `Balance`, `Balans`, `Saldo`) по счёту или кошельку без кредитного лимита. Перепроверка асимметрична: увидев `balance` — проверь, не должно ли там быть `av_balance`; увидев `av_balance` — не перепроверяй. Механической замены нет.

**Границы задачи.** Только один новый файл. Код не трогать, `build-content.ts` не трогать (это W2), выявленные дефекты клиента не чинить.

**Ворота.** Приёмку делает **второй агент, не тот, что писал**: сверить каждое утверждение документа с апстримом и с PRD, вернуть список расхождений. Документ без независимой сверки не принимается.

## W3 — `fetchBlobsByRef` в `client.ts`

**Бриф саб-агенту.** Добавить в `src/domain/github/client.ts` рядом с `fetchFileContent` (~строка 1422) функцию выгрузки тел файлов через GraphQL: алиасы `object(expression: "<ref>:<path>") { ... on Blob { text isTruncated } }`, **батчами по ~50 путей**, через существующий `publicOctokit.graphql` (~строка 949). Экспортировать из барела. Разбор `GraphqlResponseError` — рядом с `classifyPullRequestResolverError` (~строка 252).

**Три `null` обязаны различаться** и приходить наружу разными сигналами — это главное требование задачи:
- `object == null` — файла нет в этом слое (штатно, просто нет записи);
- `Blob.text == null` — бинарный файл;
- `isTruncated == true` — тело обрезано.

Слить их в один «нет файла» нельзя: легенда пакета в этом случае врёт агенту.

**Границы.** `repoRef` на слой **не заводить** — оба слоя запрашиваются из base-репозитория одним проходом, для fork-PR это проверено. `file-content-store.ts` и `use-intersections.ts` **не трогать** вообще. Батчи не объединять в один запрос: 10-секундный таймаут теряет весь пакет, потолок алиасов недокументирован.

**Ворота.** `bun run verify` зелёный; тест на различение трёх сигналов; ручная проверка на крупном банке (`cost: 1` на батч).

## W5a — чистая `buildPromptPackage`

**Бриф саб-агенту.** Создать `src/features/prompt-package/core.ts`: чистая функция `buildPromptPackage(факты) → { text, summary }`. Вход — название банка, три слоя как списки `{path, content}`, тексты выбранных документов, текст задачи. Выход — весь пакет одной строкой плюс `summary` для предпросмотра (по строке на слой включая ноль, список документов, байты, оценка токенов, список «не вошли»). Схема блоков, текст легенды и все правила — раздел «Состав пакета» в PRD #20.

**Границы.** **Ни сети, ни сторов, ни `localStorage`, ни React** — файл обязан импортироваться и тестироваться в изоляции. Легенда и шаблон — константы этого модуля, **не `i18n`**. Оценка токенов — байты UTF-8 / 4, без токенайзера и без новых зависимостей.

**Ворота.** `bun run verify` зелёный; тесты на порядок блоков, непечатаемый пустой слой, отсутствующий `layer="main"`, дословный текст легенды, счётчик на кириллице.

## Правила координатора

- **Одна задача — один саб-агент.** Не склеивай W1 с W5: проза и код требуют разного режима.
- **W1 принимает не тот агент, что писал.** Для остального достаточно ворот.
- **Ворота обязательны:** `bun run verify` (типы + тесты + секреты + линт) должен быть зелёным на каждой принятой задаче. Красный verify — задача не принята, возвращается автору.
- **Запреты, которые повторяешь каждому саб-агенту:** не трогать `file-content-store.ts` и `use-intersections.ts`; не «улучшать» соседний код (`AGENTS.md` §3); не добавлять зависимостей; не чинить известные расхождения с апстримом (`(?i)`, `types.ts:126-132`, `CreateFormatModal`, `parser.ts:32-41`) — они вне объёма и описаны в документе, а не чинятся.
- **Разногласие с ADR не переопределяй молча.** Если саб-агент упирается в «ADR-0016 требует X, а X не работает» — останови работу, вынеси решение наверх.
- **Порядок волн не нарушай:** W5b без принятых W2/W3/W4 соберёт заглушки, которые потом никто не выкинет.
