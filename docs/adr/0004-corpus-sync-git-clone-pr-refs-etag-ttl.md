# Корпус через git, свежесть через ETag и TTL

Корпус бота включает все форматы `main` и добавленные или изменённые форматы открытых PR. Пофайловая загрузка требует сотен REST-запросов при лимитах GitHub 60 запросов/час без токена и 5000 с токеном; платные функции недопустимы.

Содержимое загружается полным git-клоном небольшого текстового репозитория, затем дельтами `fetch`. Открытые PR читаются через `refs/pull/<N>/head`; полный клон позволяет локально вычислить общий коммит веток и изменённые файлы. REST нужен для списка открытых PR с заголовками и SHA, а также проверки свежести.

Входящий запрос после истечения TTL 30–60 секунд запускает два условных GET по ETag: для `main` и списка PR. Ответы 304 не расходуют лимит; git обновляет только изменившиеся ссылки. Проверок по таймеру нет. Изменения корпуса происходят намного реже TTL, поэтому ограниченное им устаревание принято ради меньшей задержки и устойчивости к всплескам.

Нужен read-only токен GitHub. Ссылки закрытых PR удаляются, вершины открытых принудительно обновляются при rebase или force-push. Снимок в памяти восстанавливается и компилируется из сохранённого клона; повторное клонирование нужно только при потере диска. После рестарта первая проверка запускается первым запросом, до обновления используется дисковый снимок.

Tarball отвергнут из-за полной перезагрузки вместо дельт, пофайловый REST — из-за расхода лимита, HEAD — из-за отсутствия дешёвого сигнала конкретных изменений. Проверка каждого SMS отвергнута из-за задержки и запросов на всплесках.
