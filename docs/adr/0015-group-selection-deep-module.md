# Выделение группы: глубокий модуль `useGroupSelection` — чистый автомат вместо реф-флага и четырёх эффектов-сбросов

## Контекст

Семантика выделения группы задана ADR-0010 (настоящее CM-выделение на скобочном диапазоне, замена сниппетом, итеративный перебор, открывающая `(` вне хит-теста). Этот ADR — про **форму кода**, не про поведение: поведение переносится byte-for-byte.

Сегодня инструмент размазан по `RegexLab.tsx` (~870 строк):

- состояние `selectedGroupIndex` плюс реф-флаг `insertionIsReplacingGroupRef`;
- четыре эффекта-сброса — на смену примера, смену regex (с исключением для взведённого флага), исчезновение группы N после вставки, уход из режима «Группы»;
- три входа (клик в поле, иконка ⌖ в таблице, гашение из списка пояснения) и обработчик вставки, взводящий флаг.

Интерфейс кластера равен его реализации. Центральный инвариант ADR-0010 — «**выделение переживает вставку сниппета**» — нигде не виден как контракт и тестируется только полным рендером `RegexLab` с CodeMirror. Самая хрупкая деталь — реф-флаг `insertionIsReplacingGroupRef`: он работает на тайминге «render → effect», ADR-0010 посвящает ему абзац-предупреждение «не упрощайте». На чистом main на `RegexLab` висит lint `noExcessiveCognitiveComplexity` (201:17) — симптом той же размазанности.

## Решение

Выделить фичу `src/features/regex-lab/` → **чистый автомат-редьюсер `group-selection.ts` (core) + тонкий хук `useGroupSelection` + `group-selection.test.ts`** — по форме intersections (ADR-0013) и bank-inventory (ADR-0014): чистая сердцевина, тонкий хук, юнит-тесты инвариантов без рендера.

### Почему здесь редьюсер, хотя ADR-0013 от него отказался

ADR-0013 сознательно не вводил полноценный редьюсер для `useIntersections`: там была горстка независимых булевых, и машина была бы церемонией. Здесь природа кластера обратная — вся боль именно в **переплетённых правилах сброса и хрупком реф-флаге**. Редьюсер их укрощает напрямую:

- **Реф-флаг становится полем состояния `armed`.** Гоночная деталь «следующая смена regex — наша вставка, не сбрасывай» из ADR-0010 превращается в чистый переход. Инвариант «переживает вставку» тестируется как данные, без React и без CodeMirror:
  `reduce(reduce(state, armReplace), regexChanged)` → индекс жив. Это deletion-test в чистом виде — ровно то, чего сегодня нет.

Редьюсер оправдан тем, что снимает конкретную задокументированную хрупкость, а не «ради глубины». Будь это снова горстка флагов — выбрали бы тонкий хук без машины.

### Состояние и словарь автомата

Состояние редьюсера: `{ selectedIndex: number | null, armed: boolean }`.

События: `toggle(N) · deselect · armReplace · regexChanged · exampleChanged · modeLeft`.

Переходы (семантика ADR-0010 дословно):

- `toggle(N)` — `selectedIndex === N ? null : N` (повторный клик/иконка схлопывает).
- `deselect` — `selectedIndex = null`.
- `armReplace` — `armed = true` (однострел; взводится перед вставкой сниппета в выделенную группу).
- `regexChanged` — если `armed` → `armed = false`, **индекс сохраняется** (итеративная замена); иначе → `selectedIndex = null` (печать, внешняя синхронизация файла, смена формата сбрасывают).
- `exampleChanged` — `selectedIndex = null` (смена примера всегда сбрасывает — отдельный триггер).
- `modeLeft` — `selectedIndex = null` (выделение — аффорданс режима «Группы»).

### «Группа N исчезла» переиспользует `deselect` — отдельного события нет

Правило ADR-0010 «после вставки сниппета без скобок группа N исчезла → выделение мягко спадает в каретку» **не требует знания токенов внутри редьюсера**. Хук и так вычисляет `range` из `selectedIndex` + токенов; когда при живом индексе `range` стал `null`, хук шлёт обычный `deselect`. Оба порядка срабатывания эффектов (`regexChanged` с `armed` и watch-эффект `range`) коммутируют — результат «null» одинаков. Редьюсер остаётся чистым: про токены и про разбор regex он не знает ничего.

### Граница шва: номер группы внутрь, `selectedIndex` + `range` наружу

Три провода пересекают границу; по каждому решено, по какую он сторону:

- **Резолв `tokenIndex → N` (клик в поле) — снаружи.** `RegexLab` через `tokenCaptureGroupMap` превращает индекс токена в номер группы и зовёт `toggle(N)`; токен вне группы → `deselect()`. Хук принимает **номер группы**, не индекс токена — так оба входа (клик и иконка ⌖) приходят одинаково, а знание «открывающая `(` отдаётся как `null`» остаётся в поле редактора (ADR-0010). Хук не зависит от токен-мапы.
- **Синхронная подсветка `activeCaptureGroup` / `activeMatchRange` — снаружи.** Это смесь `selectedIndex ?? запасной-вариант-по-токену-под-курсором`; запасной путь — подсветка активного токена (режим «Части»/наведение), к выделению группы отношения не имеющая. Хук отдаёт только `selectedIndex`, смесь собирает `RegexLab`. Тащить токенный путь в хук — шов поперёк чужого концепта (тот же отказ, что в ADR-0013 про `formatTab`).
- **`range` → CM-выделение и вставка — наружу.** Хук вычисляет `range` из `selectedIndex` + токенов и отдаёт наружу; `RegexLab` прокидывает его пропом `selectedGroupRange` в `UnifiedRegexEditor` (тот сам диспатчит CM-selection) и целит в него вставкой через `regexEditorRef`. Ref редактора хуку не место — хук даёт лишь `range` + `armReplace()`.

### Гейтинг по режиму — у вызывающего

Проверку `highlightMode === "groups"` перед `toggle` оба входа делают **снаружи**, как и резолв токена. В хуке `highlightMode` нужен ровно для одного — эффект-сброс `modeLeft` как страховка. Редьюсеру не нужно держать текущий режим в состоянии ради `toggle`.

### Поверхность хука

```
useGroupSelection({ tokens, highlightMode, regex, activeExample }) →
  { selectedIndex, range, toggle(N), deselect(), armReplace() }
```

Имя — `useGroupSelection`, по сущности целиком и буквально по термину `CONTEXT.md` «Group selection» (тот же урок, что `useIntersections`, не `useIntersectionsScope`). Операция взвода — `armReplace()`: «arm» честно сигналит однострел-флажок, `Replace` достаточен в контексте, где замена — всегда замена выделенной группы.

## Альтернативы

- **Тонкий хук без редьюсера — четыре эффекта и реф переезжают дословно.** Минимальный риск регресса, следует букве ADR-0013 «без церемонии». Отвергнуто: реф-флаг остаётся хрупким рефом, инвариант «переживает вставку» тестируется только через рендер+rerender пропа, а не как чистая функция. Здесь, в отличие от intersections, вся ценность кандидата именно в превращении реф-флага в данные — ради этого церемония окупается.
- **Отдельное событие `groupResolved(exists)` для «исчезла».** Отвергнуто: лишнее — `deselect` уже покрывает случай, порядки эффектов коммутируют. Лишнее событие раздувает словарь без выгоды.
- **`activeCaptureGroup`/`activeMatchRange` целиком в хуке.** Затягивает в модуль концепт активного токена (режим «Части», наведение), к выделению группы не относящийся, — шов поперёк границы.
- **Резолв `tokenIndex → N` внутри хука (хук держит `tokenCaptureGroupMap`).** Две сигнатуры `toggle` или фейковый токен из иконки — мутный интерфейс ради переноса однострочника.
- **Имена `armInsertReplacing()` / `keepThroughInsert()`.** Первое — жаргон (два герундия), второе прячет, что внутри взведённый флаг-однострел. `armReplace()` — компромисс.

## Последствия

- `RegexLab` теряет состояние выделения, реф-флаг и четыре эффекта-сброса; вероятно закрывается lint `noExcessiveCognitiveComplexity` (201:17).
- Инвариант «выделение переживает вставку» и все правила сброса тестируются как чистые переходы редьюсера, без CodeMirror; `renderHook` остаётся для проводки `range`/эффектов.
- Поведение переносится byte-for-byte: `RegexLab.test.tsx`, `UnifiedRegexEditor.insert.test.tsx`, `UnifiedRegexEditor.external-sync.test.tsx` переживают рефакторинг без правок и остаются регрессионной сеткой поверх нового шва.
- Спорное поведение (если всплывёт при имплементации) не чинится здесь — фиксируется отдельным кандидатом, как в ADR-0013.
- `CONTEXT.md` статья «Group selection» при имплементации уточняется лишь указанием на модуль `src/features/regex-lab` (по образцу статей «Intersections tool» / «Bank inventory»); семантика термина не меняется. Глоссарий не правится до имплементации.
