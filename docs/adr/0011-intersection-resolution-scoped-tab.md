# Разрешение пересечений через scoped-вкладку (направленный, замороженный набор) вместо модалки

## Контекст

Репозиторий запрещает пересечения regex внутри одного банка (CONTEXT.md: внутри банка не больше одного распознанного формата на SMS). В редакторе есть инструмент «Посчитать пересечения»: он делает снапшот всех форматов банка (`intersectionFormatEntries`) и для каждого формата показывает в строке файла бейдж `X / Y / Z` — всего примеров / своих совпавших / **число других форматов, чьи примеры распознаёт regex этого формата** (`calculateFormatIntersectionStats` в `src/domain/format/intersections.ts`). Метрика **направленная**: A→другие.

Сегодня правое число `Z` при `Z>0` кликабельно и открывает модалку `QuickCheckPanel` в режиме «sms-by-template» с авто-прогоном: берёт regex A, гоняет по всем SMS банка и показывает совпавшие форматы. Из модалки можно перейти на совпавший файл. Проблема: модалка — отдельная поверхность, в ней нельзя удобно ходить по взаимно пересекающимся файлам и править их, пока пересечения не исчезнут.

Хочется заменить модальный вход на навигационный: клик по числу наполняет третью вкладку файлового списка («Все файлы / Недавние / Пересечения») набором пересекающихся форматов, по которым можно ходить и править прямо в редакторе. Здесь несколько неочевидных развилок, об которые споткнётся будущий читатель, — отсюда ADR.

## Решение

**Клик по правому числу формата A больше не открывает модалку, а наполняет scoped-вкладку «Пересечения» и переключает на неё.** Набор вкладки = `A` (первым) + форматы, чьи примеры распознал regex A. Строки рендерятся теми же правилами, что и обычный файловый список (бейдж `X / Y / Z`, индикаторы статуса, ссылка на репозиторий, выбор файла открывает его в редакторе).

### Набор направленный и включает сам A

Состав = `A` + направленный набор `A→others` (форматы, чьи примеры распознаёт regex A) — ровно тот же набор, что показывала модалка, плюс сам A как «корень» конфликта. Симметричное замыкание (и те, кто ловит примеры A) и транзитивная связная компонента отвергнуты: они меняют семантику метрики и заставляют список «прыгать». Направленность сохраняется той же, что у бейджа, — один источник истины для счётчика и списка.

### Набор заморожен на момент клика

Состав вкладки фиксируется при клике по числу и **не меняется**, пока пользователь не кликнет по числу другого формата или не запустит «Посчитать пересечения» заново. При этом **бейджи внутри строк пересчитываются вживую** (через существующий `handleFormatRegexBlurAfterEdit` → пересчёт `formatIntersectionStats`): по мере правки `Z` падает к нулю. Прогресс читается по бейджам, а не по исчезновению строк.

Живое исчезновение строк (формат пропадает из списка, как только пересечение убрано) отвергнуто: строка, которую правишь, выпрыгивает из-под курсора. Замороженный набор даёт стабильную рабочую область — держишь перед глазами все конфликтующие форматы и правишь их, пока все `Z` не станут нулём.

### Навигация по графу: число кликабельно и внутри вкладки

Правое число во вкладке «Пересечения» работает так же, как во «Все файлы»: клик по `Z` формата B **переподнимает** набор под B (`B` + те, чьи примеры ловит regex B). Это единый жест навигации по «клубку» конфликтов без возврата на «Все файлы». Переподнятие — по явному действию, набор не прыгает сам.

### Клик по числу не трогает редактор

Клик по числу делает ровно две вещи: наполняет набор и переключает таб. Что открыто в редакторе — то и остаётся (в типичном случае A и так уже открыт — число кликают у редактируемого файла). A стоит первым в списке, открыть его — один клик по строке. Это разделяет «показать набор» и «сменить редактируемый файл».

### Жизненный цикл вкладки

Третья вкладка появляется **при первом клике** по правому числу (до этого табов два, как сейчас) и живёт до конца сессии, держа последний набор. Переключаться между «Пересечения» и «Все файлы»/«Недавние» можно свободно. Пустых состояний «посчитано, но не выбрано» нет — вкладка существует только как результат клика по числу. Поиск во вкладке фильтрует внутри scoped-набора; счётчик в шапке показывает размер набора. Удалённые/сброшенные файлы из набора просто отсутствуют; если набор сжался до одного A — это сигнал «у A конфликтов больше нет».

### Модель данных

`FormatIntersectionStat` расширяется: к `intersectingOtherFormats: number` добавляется `intersectingFormatPaths: string[]` — пути форматов, чьи примеры распознал regex. Клик по числу (в любом табе) берёт `intersectingFormatPaths` + сам формат → scoped-набор. Один источник и для счётчика, и для списка.

### Что убирается

Срезается **только вход «пересечения → модалка»**: `handleOpenSmsByTemplateForIntersection`, авто-прогон по intersection-контексту и связанная проводка. Сама `QuickCheckPanel` остаётся — она обслуживает кнопки сайдбара «Поиск шаблона по СМС» и «Поиск СМС по шаблону» (отдельная фича, не про пересечения).

## Альтернативы

- **Набор только `A→others` без самого A.** Отвергнуто: без A в списке неудобно прыгать туда-обратно и сравнивать; A — корень конфликта.
- **Симметричный/транзитивный набор (связная компонента).** Отвергнуто: меняет направленную семантику метрики на другую, список прыгает, нужен граф и обход — сложность без явного спроса.
- **Живой пересчёт состава (строки исчезают сразу).** Отвергнуто: редактируемая строка выпрыгивает из-под курсора. Замороженный набор + живые бейджи дают и стабильность, и прогресс.
- **Число во вкладке некликабельно (только индикатор).** Отвергнуто: чтобы перейти к конфликтам B, пришлось бы возвращаться на «Все файлы»; асимметрия рендера между табами.
- **Клик по числу открывает A в редакторе.** Отвергнуто: вырывает из текущей правки, если кликнул число чужого файла; смешивает навигацию по списку со сменой редактируемого файла.
- **Вкладка всегда видна и кликается напрямую.** Отвергнуто: часто пустой таб, несколько разных пустых состояний. Вкладка как «результат клика по числу» проще.
- **Убрать `QuickCheckPanel` целиком.** Отвергнуто: она обслуживает два рабочих инструмента поиска по СМС, не связанных с пересечениями.

## Последствия

- **Новый редакторский концепт.** В `CONTEXT.md` при имплементации появится термин для scoped-вкладки пересечений (инструмент уровня редактора; на устройстве и в боте его нет). Глоссарий обновляется при имплементации, не раньше.
- **Расширение контракта `FormatIntersectionStat`** (`intersectingFormatPaths`) — затрагивает `intersections.ts` и места рендера бейджа.
- **Направленность и заморозка набора задокументированы здесь**, потому что в коде причина не видна: будущий читатель увидит несимметричный, не обновляющийся вживую список и решит, что это баг. Это осознанный выбор (стабильная рабочая область + единый источник истины с бейджем).
