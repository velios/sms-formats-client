# Согласованные ревизии, документы и публикация PR

Статус: принято в реализации аудита от 29 сентября 2026 года.

Редактор, проверки и пакет агента читают одни файлы, но раньше кеш определял их по номеру PR, а не по прочитанному коммиту. Загрузка базовой ревизии могла занять место head. Проверка публикации видела только изменённые форматы, а завершение публикации удаляло и правки, появившиеся после начала записи.

Удалённое тело определяется репозиторием, commit SHA и путём. Один кеш обслуживает одиночные REST-запросы редактора и пакетные GraphQL-запросы пакета агента. Повторное чтение того же коммита не требует инвалидирования; новая ревизия получает другой ключ. Ошибка загрузки не превращается в пустой документ. Перед проверкой всего банка должны быть получены все его действующие файлы.

Действующий банк получается наложением локальных документов и удалений на head-снимок. Отсутствие исходного файла выражается отдельно от пустого текста. Исходный документ хранится один раз; regex, колонки и примеры выводятся из него. Команды undo/redo текстового поля и CodeMirror направляются в историю этого документа. Внешняя синхронизация редактора не является пользовательской правкой. Разбор убирает только разделители файла, сохраняя литеральные пробелы regex и крайние переносы строк примеров. Режим чтения блокирует все команды изменения документа, включая историю.

Пакет агента сохраняет три исторических слоя. Его базовый слой берётся из общего коммита веток PR и main (`merge base`), который сессия хранит как `baseSha`, а слой PR — из её head. Список изменений PR описывает отличия от этого общего коммита. Использование текущей вершины main смешало бы в итоговом банке изменения, которых нет в head PR. Явное удаление исключает файл из итоговой проекции; отсутствие записи в разреженном слое не удаляет его. Переименование передаётся существующими блоками записи и удаления.

Публикация захватывает набор локальных документов, проверяет весь банк и передаёт SHA проверенной сессии в атомарную запись GitHub. Изменение head или документов во время проверки блокирует запись. После успешного коммита подтверждается только опубликованный набор в исходной области PR. Более поздние правки получают новую исходную ревизию и остаются черновиками. Исчезновение захваченного документа также выражает последующее действие: удалённый или переименованный новый файл получает черновик удаления старого пути после подтверждения записи. Ошибка последующего чтения показывает, что коммит уже опубликован, а обновление сессии не завершилось.

Это заменяет решение об обходе кеша в [ADR-0016](0016-prompt-package-deep-module.md): прежнее ограничение ключа устранено. Чистая сборка пакета и получение данных снаружи сохраняются. Для [ADR-0017](0017-import-answer-deep-module.md) сохраняется запись через существующие операции черновиков; пересчёт получает явный снимок после записи и не ждёт очереди рендеринга. Отдельный слой предложений агента и пакетный API стора не вводятся.

Синхронизация корпуса бота подтверждает метаданные только после чтения соответствующего Git-ref. Ответ `304` не отменяет повторную попытку ранее неудачного fetch. Сетевые команды выполняются асинхронно; сохраняются один выполняющийся цикл обновления и последний пригодный корпус. Это уточняет [ADR-0004](0004-corpus-sync-git-clone-pr-refs-etag-ttl.md), не меняя состав корпуса.
