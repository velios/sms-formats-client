# Согласованные ревизии, документы и публикация PR

Статус: принято.

Редактор, проверки и пакет агента должны читать согласованные ревизии файлов. Публикация должна проверять весь действующий банк и сохранять локальные правки, не вошедшие в отправленный коммит.

Удалённое тело определяется репозиторием, commit SHA и путём. Общий кэш обслуживает REST редактора и GraphQL пакета; новая ревизия получает новый ключ, прежняя не требует инвалидации. Ошибка загрузки, отсутствие файла и пустой текст различаются. Действующий банк — head с наложенными локальными документами и удалениями; для проверки загружаются все его файлы.

Исходный документ хранится один раз, regex, колонки и примеры выводятся из него. Текстовые поля и CodeMirror используют общую историю; внешняя синхронизация не считается правкой. Разбор убирает только разделители, сохраняя литеральные пробелы regex и крайние переносы примеров. Режим чтения блокирует изменения, включая историю.

Пакет содержит три слоя ревизий: база — общий коммит PR и main (`merge base`, сохранённый как `baseSha`), PR — head сессии, локальные правки — черновики. Изменения PR считаются относительно этой базы. Текущая вершина main отвергнута, поскольку содержит изменения вне PR. Явное удаление исключает файл, отсутствие записи в разреженном слое — нет; переименование выражается записью и удалением.

Публикация захватывает локальные документы, проверяет весь банк и атомарно записывает с SHA проверенной сессии; изменение head или документов при проверке блокирует запись. Подтверждается только захваченный набор исходного PR. Поздние правки сохраняются с новой исходной ревизией. Если захваченный новый файл после начала публикации удалён или переименован, после подтверждения остаётся черновик удаления старого пути. Сбой последующего чтения сообщается как успешный коммит с незавершённым обновлением сессии.

[Пакет](0016-prompt-package-deep-module.md) использует общий кэш, чистую сборку и внешнее получение данных. [Импорт](0017-import-answer-deep-module.md) использует существующие операции черновиков и явный снимок после записи для пересчёта, без ожидания рендера, нового слоя предложений или пакетного API стора.

Бот подтверждает метаданные корпуса только после чтения соответствующего Git-ref: 304 не отменяет повтор неудачного fetch. Сеть асинхронна, одновременно выполняется один цикл, последний пригодный корпус сохраняется. Состав корпуса задан [ADR-0004](0004-corpus-sync-git-clone-pr-refs-etag-ttl.md).
