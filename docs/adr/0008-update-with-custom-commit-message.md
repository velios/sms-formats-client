# Причина обновления PR в сообщении коммита

Одинаковый заголовок PR во всех коммитах скрывает причины обновлений. Пользователь задаёт причину в сообщении самого коммита, чтобы она была связана с изменением одной операцией публикации.

«Обновить Pull Request» открывает окно с однострочным заголовком и необязательным описанием. Авторское обновление доступно при непустом после обрезки краёв заголовке; описание отделяется пустой строкой. Всегда доступный вариант «Обновить со стандартным заголовком» использует заголовок PR и игнорирует введённые поля. API принимает необязательное сообщение коммита и при его отсутствии или пустоте также использует заголовок PR.

Проверки актуальности вершины, прав записи, наличия изменений, допустимых путей, валидации и токена выполняются до открытия окна и повторяются перед публикацией: за время ввода вершина могла измениться. Публикация — один атомарный push без отдельного комментария и механизма повторной отправки. Выбор сообщения — отдельный шаг перед публикацией, с быстрым стандартным вариантом.

Комментарий в обсуждении отвергнут: причина отделялась от истории изменений. Постоянное использование заголовка PR отвергнуто как исходная причина неразличимости обновлений. Обязательная авторская причина отвергнута из-за лишнего действия при мелких правках.
