# Причина обновления PR — авторское сообщение коммита (заголовок + описание), а не комментарий в ленту

## Контекст

«Обновить Pull Request» сегодня — действие в один клик: `updatePullRequestHead` (`src/domain/github/client.ts`) пушит новый коммит в head-ветку PR, а сообщением коммита берётся **заголовок PR**. Значит все апдейты одного PR дают коммиты с **одинаковым** текстом — отличить «почему был этот пуш» по истории нельзя. Пробел: тот, кто читает PR (в первую очередь ревьюер `zenmoney/sms-formats`), не видит причину очередного обновления.

Первый подход (комментарий в ленту обсуждения PR через `issues.createComment`) собрали и **попробовали вживую — не зашло**: причина-записка жила отдельно от самого изменения, лента и история коммитов расходились, а к этому добавлялась возня с best-effort-постингом и фазой повтора при сбое коммента. Поэтому развернулись к очевидному месту для «почему этот коммит» — **сообщению коммита**, которое изначально и было самым прямым кандидатом.

## Решение

Причина обновления — **авторское сообщение коммита**, которое пользователь задаёт перед пушем. Клик по «Обновить Pull Request» открывает модалку с двумя полями:

- **Заголовок коммита** — `<input>` (однострочный, как требует git-subject).
- **Описание коммита** — `<textarea>`, необязательное.

Две кнопки:

- **«Обновить»** (синяя) — активна только когда заголовок непустой (с учётом trim). Коммитит с собранным сообщением.
- **«Обновить со стандартным заголовком»** (серая) — всегда доступна; коммитит как сегодня, сообщение = заголовок PR. Если пользователь что-то ввёл в поля, но нажал серую — введённое игнорируется (явный выбор «хочу дефолт»).

### Сборка сообщения

По git-конвенции subject/body: заголовок, пустая строка, тело.

- только заголовок → сообщение = `title`;
- заголовок + описание → `title` + `\n\n` + `description`;
- серая кнопка → `commitMessage` не передаётся, `updatePullRequestHead` подставляет заголовок PR.

Сборку делает клиент-код после нажатия (UI несёт только два сырых поля). `updatePullRequestHead` получил необязательный параметр `commitMessage`: если он непустой — идёт в коммит, иначе фолбэк на заголовок PR.

### Префлайт и атомарность

Префлайт-проверки (`stale` / `read-only` / `no-changes` / `invalid-scope` / `validation-failed` + токен) гоняются **на первом клике, до открытия модалки**: не просим заполнять поля для апдейта, который всё равно не пройдёт. Перед самим пушем префлайт прогоняется ещё раз (между открытием модалки и сабмитом пользователь печатает — за это время head мог уехать). Сам апдейт — **одна операция**: push коммита либо прошёл, либо нет; второго вызова к GitHub (как был коммент) больше нет, поэтому никакого best-effort и повтора.

## Альтернативы

- **Комментарий в ленту обсуждения PR (`issues.createComment`).** Изначально выбранный путь — собрали и попробовали. Отвергнут после практики: записка отрывалась от изменения (лента ≠ история коммитов), а ради «PR обновлён, но коммент не отправлен» приходилось тащить best-effort и фазу повтора. Сообщение коммита кладёт причину туда, где её ищут, одной атомарной операцией.
- **Хеш-ссылка на коммит как авто-префикс к тексту** (`9112dc0 <текст>`). Рассматривали как точечное исключение к «без обвязки». Отпало вместе с самим подходом «коммент»: при авторском сообщении коммита трассировка к пушу встроена by design — текст и есть сообщение этого коммита.
- **Оставить сообщение коммита = заголовку PR всегда (как было).** Отвергнуто: это и есть исходный пробет — все апдейты неразличимы. Серая кнопка сохраняет это поведение как осознанный дефолт, но не как единственный режим.
- **Обязательное сообщение на каждом апдейте.** Отвергнуто: трение на мелочах. Серая кнопка даёт быстрый дефолтный путь без полей.

## Последствия

- **Контракт `updatePullRequestHead` расширен** необязательным `commitMessage`; существующие вызовы (включая `PublishPanel`) продолжают работать с фолбэком на заголовок PR.
- **Фича комментария-в-ленту выпилена целиком**: `commentOnPullRequest`, её мок в тестах и i18n-ключи (`commentLabel`/`commentFailed`/`retryComment` и т.п.) удалены; в хуке исчезли `retryComment` и discriminated-исход `comment-failed`/`aborted`/`done`.
- **«Обновить PR» перестаёт быть строго однокликовым.** Между кликом и пушем — модалка с двумя полями. Быстрый путь сохранён серой кнопкой «Обновить со стандартным заголовком».
- **Глоссарий.** Появляется понятие «сообщение коммита (заголовок + описание)» как авторская причина обновления. `CONTEXT.md` обновляется **при имплементации**, не раньше.
