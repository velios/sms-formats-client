# Помощники авторинга regex (cookbook + библиотека сниппетов) собираются на этапе сборки встроенными средствами Bun, без новых клиентских библиотек

## Контекст

Редактору regex-форматов нужны два помощника авторинга:

1. **Cookbook** — полный справочник лучших практик написания regex (первоисточник: `transaction_sms_regex_cookbook.md` в репозитории `velios/sms-formats`, markdown с таблицами). Это «знание целиком», которое читают.
2. **Библиотека сниппетов** — интерактивный каталог распространённых кусков regex по сущностям (паттерн + где применять + пример + грабли), клик по которым вставляет фрагмент в regex. Это «вставляемые куски».

Два ограничения формируют решение:

- **Клиент — браузерный SPA на Vite.** Bun у нас работает только на сервере (бот) и как раннер тулинга; в браузер, куда отгружается редактор, серверные API Bun не попадают. Значит любой рендер/парсинг «на лету в браузере» потребовал бы **клиентской** библиотеки.
- **Не заводим новые библиотеки.** Хотим обойтись встроенными возможностями.

Дополнительно: cookbook живёт в **отдельном** репозитории и поддерживается независимо; а сниппеты должны быть **редактируемы не-кодером** — сторонним редактором, без захода в код. Версия Bun: проект пиннит **Bun 1.3.12 через mise** (`mise current bun` → 1.3.12), и в ней `Bun.markdown.html()` уже доступен — апгрейд не требуется. (Отдельный глобальный `~/.bun/bin/bun` = 1.3.6 этого API не имеет — для сборки используем bun проекта через mise.)

## Решение

Оба помощника собираются **на этапе сборки** скриптом-раннером Bun, встроенными средствами, и в бандл попадает уже готовый результат. Новых клиентских библиотек не вводим.

### Cookbook

- В клиент-репо **вендорим копию** `.md` (снапшот; синхронизация с `velios/sms-formats` ручная).
- Build-скрипт прогоняет md через **`Bun.markdown.html()`** (GFM-таблицы включены — cookbook их активно использует) и кладёт готовую HTML-строку в бандл.
- Клиент отрисовывает её в **полноэкранной модалке** (`ModalDialog`) через `dangerouslySetInnerHTML`. Источник доверенный (наш документ, фиксируется на сборке), поэтому инъекция HTML здесь приемлема.
- Сборку контента гоняет **bun проекта (1.3.12 через mise)**, где `Bun.markdown` доступен — отдельный апгрейд не нужен.

### Библиотека сниппетов

- Источник — **человекоредактируемый `.toml`-файл** в клиент-репо: на каждый сниппет именованные поля (`pattern`, `entity`, `desc`, `trigger`, `example`, `gotcha`, маркер дефолт/альтернатива). Литеральные строки TOML (`'...'`/`'''...'''`) хранят regex **дословно**, без экранирования бэкслэшей.
- Build-скрипт читает TOML **нативным импортом Bun** (без либ и без своего парсера) и собирает типизированный каталог, который потребляет приложение.
- UI — **модалка-пикер** (как `ColumnPickerModal`): поиск, группировка по сущностям, карточки со всеми полями; клик **вставляет сниппет в позицию курсора** CodeMirror и закрывает модалку. Легаси-паттерны «не копировать» **карточками не показываются** (по желанию — строкой в граблях). Проза сниппетов — **ru**; локализуются ru/en только структурные UI-метки.
- Каталог сниппетов и cookbook — **два независимых источника**: каталог наполняется единоразово из раздела 3 cookbook (bootstrap), дальше живёт сам и может расходиться.

### Сниппеты без группы захвата

Не каждый сниппет — capture-группа сущности. Часть каталога — **вспомогательные куски без скобок**, и это **нормальная, ожидаемая** категория, а не исключение. Их можно свободно добавлять для распространённых сочетаний.

- **Что сюда входит.** Склейка и якоря (`\s+`, `\s*`, `.*?`, `.*`) и **пропуск лишнего токена** — куска SMS между сущностью и её правым якорем, который не идёт ни в одну колонку (дубликат валюты символ+ISO вида `kr SEK`, служебное слово). Помечаются `group = "glue"`; у `pattern` нет скобок.
- **Когда применимы.** Когда узкая группа сущности (напр. `(\S+)`) иначе растянулась бы через не-сущностный токен до якоря. Тогда после группы ставим `.*?` без захвата, и он проглатывает лишнее, не попадая в `value`: `(\S+).*?balance:`. Это дешевле и устойчивее, чем хардкодить пропускаемый токен (`SEK`/`[A-Z]{3}`), — см. cookbook 3.3, грабли «лишний токен между валютой и правым якорем».
- **Карточки показываются как обычные**, с теми же полями (`desc`, `trigger`, `example`). Дефолт/альтернатива маркируются как у группных сниппетов.
- **Взаимодействие с заменой группы (ADR-0010).** Такой сниппет рассчитан на **вставку в каретку**, а не на замену выбранной группы. Если вставить его поверх выделенной группы N, число групп упадёт и группа N исчезнет → выделение **мягко сбрасывается** (`resolveCaptureGroupRange` вернёт `null`, см. 0010, «Переразрешение по стабильному индексу N»). Это ожидаемое поведение, не баг.

## Альтернативы

- **Внешняя ссылка на GitHub для cookbook.** Ноль зависимостей, всегда «живая» версия, повторяет существующий паттерн внешних ссылок. Отвергнуто как основной путь: хотели чтение внутри приложения. Может остаться escape-hatch'ем «открыть на GitHub» рядом со снапшотом.
- **Клиентская md-библиотека (markdown-it/marked) + fetch raw в рантайме.** Всегда актуально, но это **новая клиентская зависимость** + обработка сетевых ошибок + стилизация. Отвергнуто ограничением «без новых либ».
- **Снапшот, замороженный на сборке (выбрано), vs live-fetch.** Приняли осознанный минус: cookbook в приложении = снапшот, не живой; взамен — воспроизводимость, офлайн и отсутствие сетевой обвязки.
- **Сниппеты как рукописный TS-каталог в коде.** Первоначально так и решили; развернули — требует правок кода, исключает стороннего редактора-не-кодера.
- **Сниппеты, парсимые из md cookbook (на лету/на сборке).** Автосинхрон, но проза/таблицы md плохо читаются машиной — та самая хрупкость, плюс мы намеренно расцепили два источника.
- **Источник сниппетов — markdown со строгой схемой.** Документно и в стиле cookbook, но нужен **свой парсер** + валидация, а позиционные поля хрупки к правкам не-кодера.
- **Источник сниппетов — YAML-фронтматтер.** Привычно, но YAML в Bun **не нативен → новая библиотека**, плюс бэкслэши regex — известный источник скрытых ошибок экранирования. Отвергнуто.

## Последствия

- **Сборка контента зависит от рантайма Bun** с `Bun.markdown`. Апгрейд не нужен: проект пиннит Bun 1.3.12 через mise, API уже есть. Важно гонять контент-скрипт именно bun'ом проекта (mise), а не глобальным `~/.bun` 1.3.6.
- **Новый build-шаг** (скрипт + npm-скрипт), прогоняющийся перед `vite build` и питающий бандл (HTML cookbook + типизированный каталог сниппетов).
- **Два вендоренных независимых источника** в клиент-репо (`.md` снапшот + `.toml` сниппетов) требуют ручной дисциплины синхронизации.
- **`UnifiedRegexEditor` получает императивный API вставки в позицию курсора** (ref + транзакция CodeMirror) и запоминание последней каретки — модалка забирает фокус.
- **`dangerouslySetInnerHTML`** применяется только к нашему доверенному build-time HTML cookbook, не к произвольному вводу.
- **Глоссарий.** Появляются термины «сниппет», «библиотека сниппетов», «источник сниппетов (TOML)». `CONTEXT.md` обновляется **при имплементации**, не раньше.
