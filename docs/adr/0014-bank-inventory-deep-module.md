# Инвентарь банка: единые записи с независимыми статусами

Списку файлов, проверкам и публикации нужны согласованные сведения о локальных изменениях, удалениях и изменениях PR. Независимые множества заставляют потребителей собирать статус и повторять классификацию отправителей и неподдерживаемых файлов.

Чистая `buildBankInventory` и тонкий `useBankInventory` формируют инвентарь всего банка без собственного состояния, редьюсера и инъекций. Хук сам подписывается на черновики; остальные факты получает параметрами. Каждая упорядоченная запись имеет класс `format`, `senders` или `unsupported` и два независимых статуса: локальный относительно head и статус изменений источника. Локально различаются создание, изменение, удаление и отсутствие правки; в источнике — добавление, изменение, удаление, неподдерживаемость и отсутствие изменения. Исходная ревизия источника определяется [ADR-0018](0018-coherent-revisions-and-publishing.md).

Инвентарь знает видимость удалённых файлов и признак локального создания; исходное удаление скрывает файл только при отсутствии локальной правки. Для `unsupported` локальный статус всегда неизменён: эти файлы не редактируются. `senders.txt` — обычная запись своего класса. Панель выбирает приоритет маркеров при двух изменениях, раскладку классов, поиск и вкладки; инвентарь определяет факты и порядок внутри класса.

Кроме записей доступны только выборки с реальным именованным потребителем: форматы с изменёнными сверху для навигации, живые пути для поиска и пересечений, пути слоёв пакета промта. Инвентарь классифицирует пути; загрузка действующих тел и полная проверка банка выполняются общим механизмом снимка по ADR-0018.

Выбор источника фактов из сессии, стора или загрузки PR и готовность сессии остаются снаружи; цепочка определяется в одном месте. Входные записи допускают неизвестный вид изменения: он даёт статус `changed`, явно отражая потерю точности. Сборка данных публикации, включая изменения других банков, тоже остаётся в потоке публикации. Правила статусов проверяются чистой функцией.

Интерфейс только из списка и `statusOf` отвергнут, поскольку заставил бы потребителей повторять фильтрацию. Экспорт множества промежуточных наборов отвергнут, поскольку сохраняет сборку семантики снаружи. Один общий статус отвергнут, поскольку файл может измениться локально и в PR одновременно. Загрузка внутри инвентаря отвергнута как смешение производных данных и жизненного цикла сессии. Данные публикации внутри отвергнуты как расширение за пределы банка. Охват только форматов отвергнут из-за повторной классификации остальных файлов. Инъекция чтения черновиков отвергнута как граница без второго адаптера.
