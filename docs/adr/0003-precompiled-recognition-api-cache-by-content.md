# Предкомпилированное API в recognition-ядре; кэш компиляции по содержимому/SHA, не по идентичности

## Контекст

`regexesBySms` перекомпилирует **все** regex на **каждый** вызов. Для Recognition Bot, который гоняет один и тот же корпус (сотни форматов main + изменённые форматы 20–40 открытых PR) по потоку входящих SMS, это перекомпиляция всего корпуса на каждое сообщение. При этом handoff требует не писать в боте свой `new RegExp`/`.test()` (единый источник правды о матчинге). Эти два требования конфликтуют: переиспользование ядра «как есть» означает расточительную перекомпиляцию.

## Решение

Расширить ядро аддитивным API:

```ts
export interface CompiledRegex { regex: RegExp | null; error: string | null; }
export function compileRegexes(regexes: string[]): CompiledRegex[];
export function recognizeWithCompiled(compiled: CompiledRegex[], sms: string): SmsRecognition[];
```

`compileRegexes` идёт через тот же `tryCompile` (флаг `d` + fallback) и сохраняет семантику «пустой regex → не ошибка», «невалидный → error». `recognizeWithCompiled` нормализует SMS один раз через `cleanText` и тестирует против готовых `RegExp[]`, сохраняя инвариант выравнивания по индексам. `regexesBySms` переписывается как `recognizeWithCompiled(compileRegexes(regexes), sms)` — **один** путь матчинга на весь проект.

Бот компилирует корпус один раз на refresh снапшота и переиспользует `RegExp[]` до устаревания.

## Инвариант консистентности

Скомпилированный regex кэшируется **по содержимому или явной версии (PR head SHA)**, никогда по голому идентификатору (путь файла / id формата). Иначе правка regex под тем же id вернула бы устаревший компилят. Кэширование — свойство вызывающей стороны, а не ядра: функции ядра остаются чистыми (строки → результат, без состояния между вызовами). Бот ключует кэш по SHA+содержимому и инвалидирует по TTL-refresh; фронтенд не кэширует вовсе — компилирует из живых строк на каждое нажатие, поэтому всегда консистентен с правками в драфте/PR.

## Альтернативы

- **Гонять `regexesBySms` на каждый SMS**: честно переиспользует ядро, но перекомпилирует весь корпус на каждое сообщение — ровно та расточительность, которую устраняем.
- **Бот компилирует сам через `tryCompile` + свой `.test()`**: дублирует семантику пустого/невалидного regex и нарушает единый источник правды о матчинге — риск разойтись с устройством.
