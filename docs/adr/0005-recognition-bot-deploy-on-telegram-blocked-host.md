# Деплой бота при двусторонней блокировке Telegram

Хост бота публично доступен, но блокирует исходящие обращения к Bot API и входящие вебхуки Telegram. Бот разворачивается отдельным контейнерным приложением Dokku через GitHub Actions; образ содержит самодостаточный исполняемый файл.

Исходящие запросы идут через локальный мост HTTP→SOCKS на доступный внешний узел. Входящий вебхук регистрируется на отдельном доступном Telegram релейном хосте: он завершает TLS и передаёт только секретный путь по HTTPS на reverse-proxy хоста бота, затем на непривилегированный локальный порт процесса.

Домен вебхука обязательно принадлежит релею и задаётся отдельно от домена хоста бота; подстановка домена хоста при отсутствии настройки запрещена, регистрация должна завершаться ошибкой. Бот проверяет `X-Telegram-Bot-Api-Secret-Token`, который релей передаёт без изменения. Секретный путь — дополнительная защита; остальные пути возвращают 404. Исходные SMS не логируются.

Две конфигурации синхронизируются вручную при смене пути. Хосту бота нужен валидный TLS для проверки имени релеем. Ответы зависят от работоспособности исходящего моста даже при исправной доставке вебхуков.

Прямой вебхук отвергнут из-за блокировки. Long polling через исходящий прокси остаётся допустимым запасным вариантом; вебхук выбран благодаря уже существующей релейной инфраструктуре, меньшей задержке и единому способу деплоя ботов.
