# Импорт ответа: разбор и границы — чистые функции, запись — существующий стор черновиков, показ — структурный

## Контекст

Workspace банка получает обратную дорогу инструмента «AI промпт»: пользователь вставляет (или загружает файлом) **ответ агента** на пакет промта, видит предлагаемые изменения и записывает их в черновики банка — целиком, без пофайлового выбора. Требования и поведение — в PRD; здесь только форма кода.

Ответ — недоверенный текст в псевдо-XML легенды пакета (`<file>` — полное тело, `<delete>` — с причиной, `<rename>` — узнаём, но не поддерживаем; всё вне блоков — проза). Всё, во что импорт приземляется, уже существует:

- **Черновики** (`useDraftStore`, скоуп `pr:<N>`): `DraftEntry` несёт `content` / `remoteContent` / `baseSha` / `isDeleted`, есть `setDraft` и `markDeleted`, per-path undo/redo и пофайловый откат `resetFileToRemote`. Словарь черновиков совпадает со словарём ответа один в один; решение 1 карты (#22) — новой сущности «предложение агента» нет.
- **Пересечения** — `useIntersections.calculate()`: полный честный расчёт по действующим версиям, галочке «Пересчитать пересечения» нечего изобретать.
- **Тела head-ref** — ленивый кэш `useFileContentStore` (`fetchFileContent`), ключ PR-овый — импорт живёт в workspace того же PR.
- **Структура формат-файла** — `parseFormatFile` (`src/domain/format/parser.ts`); раскраска regex — `buildPatternHighlightPlan` (`pattern-highlight.ts`).

Решения добыты прототипами: грамматика и форма результата — `prototype/answer-parser` (#26), экран — вариант D на `prototype/import-screen`, коммит `4cd4a7b` (#27); показ «было → стало» — исследование `research/import-diff-rendering` (#24); границы применимого — #25. Прототипы — источник решений, не кода: модуль пишется заново, расхождение реализации экрана с `VariantD.tsx` решается в пользу прототипа.

## Решение

Новая фича `src/features/import-answer/`: чистая сердцевина (разбор + границы) плюс тонкий хук `useImportAnswer` плюс модалка. Форма — как у ADR-0013/0014/0015/0016.

Контракт шва:

- **Разбор — чистая `parseAnswer(text) → ParsedAnswer`.** Грамматика **построчная** — не выбор, а зеркало печати пакета (`prompt-package/core.ts:109`, блок пишется `<tag …>\n${body}\n</tag>` без экранирования): открывающий и закрывающий теги — строки целиком, тело — всё между ними **байт в байт**. Поэтому `<`/`>` внутри regex и пустая секция `-----COLUMNS-----` не ловушки *по построению*, а любой незнакомый тег — проза. Результат — размеченное объединение:

  ```ts
  type AnswerChange =
    | { kind: "write";  path: string; content: string; line: number }
    | { kind: "delete"; path: string; reason: string;  line: number };

  interface AnswerProblem { kind: AnswerProblemKind; line: number; excerpt: string }

  type ParsedAnswer =
    | { status: "broken"; problems: AnswerProblem[]; prose: string }
    | { status: "parsed"; changes: AnswerChange[]; prose: string; problems: AnswerProblem[] };
  ```

  Потеря блока (`unclosed`, `orphan-close`, `malformed-open`, `empty-path`) → `broken`: поля `changes` нет физически, нарисовать над ним кнопку импорта невозможно — решение 3 карты живёт в типе. Остальные проблемы (`duplicate-path`, `conflicting-path`, `unsupported-rename`) не рушат импорт. `prose` — весь текст вне блоков одним куском — есть в обеих ветках; пустой `changes` при `parsed` — рабочий исход «импортировать нечего». Честная оговорка: **каталог поломок сконструирован, а не наблюдён** — корпус (`.agents/research/agent-response-corpus/`) не дал ни одной, всё проверено синтетикой.
- **Порядок применения = порядок ответа, побеждает последний блок по пути.** Единственное решение, живущее не в типе, а в договорённости, — потому оно явной строчкой и здесь, и в тестах. Парсер дубли не разруливает — только называет (`duplicate-path`).
- **`<rename>` узнаём, но отказываем** (`unsupported-rename`): в корпусе 0 из 4 — консолидацию агенты делают парой `<file>` + `<delete>`; полная поддержка стоит отдельного вида строки на экране и доработки `renameDraft` (`store/index.ts:374` выходит, если черновика по старому пути нет). Не узнавать нельзя: блок утёк бы в прозу, и изменение, обещанное легендой, потерялось бы молча.
- **Границы — чистая функция от `(bankPath, path)`, белый список двух форм** (#25): `<bankPath>/senders.txt` и `<bankPath>/formats/<имя>.txt`, имя без слэшей, из символов §5 `format-rules.md`. Существующая `isBankFormatFilePath` (`domain/format/file-path.ts`) **не переиспользуется**: она мягче (`startsWith` + `endsWith` пропускают подпапку) — граница заводит свою строгую проверку, не ослабляя её задним числом. Пост-классификация причины («другой банк», «путь ведёт наружу», …) — отдельная функция *только ради сообщения*: решение принимает белый список, классификация может промахнуться формулировкой без последствий. Нарушение → отказ целиком, форма отказа общая с отказом парсера. Содержимое тел не проверяется ни структурно, ни компиляцией regex — `(?i)` проходит CI апстрима, но не браузерный движок, проверка браковала бы корректные ответы.
- **Запись — существующими `setDraft` / `markDeleted` в цикле, стор новых методов не получает.** Для файла без черновика `baseSha` берётся из дерева source, `remoteContent` — добытое действующее тело; история per-path создаётся как от ручной правки, поэтому undo и `resetFileToRemote` работают без единой доработки.
- **Добыча тел — снаружи, в хуке.** Показ «было → стало» и `remoteContent` записи требуют действующие тела всех затронутых путей: черновик бесплатен (`DraftEntry.content`), остальное — head-ref через существующий `fetchFileContent`/кэш. Затронутых путей мало (у Сбера 14), пофайловый REST достаточен. Частичного показа нет: ошибка загрузки → сообщение с «Повторить», импорт недоступен — половинчатое «было» врёт так же, как половинчатый пакет (ADR-0016).
- **Показ — структурный, без текстового diff как несущей конструкции** (#24): формат-файл раскладывается существующим `parseFormatFile` — regex двумя строками «было»/«стало» с раскраской `buildPatternHighlightPlan`, колонки двумя строками, примеры списком добавленных/убранных; оба состояния одновременно. База сравнения — действующая версия (черновик поверх PR); слой `main` не выгружается. `presentableDiff` из `@codemirror/merge` — опциональное украшение внутри regex-строки (ноль новых транзитивных пакетов); `MergeView`/`unifiedMergeView` не поднимаются.
- **Пересчёт пересечений — существующий `calculate()`** по галочке (включена по умолчанию, **не липкая**): если инструмент ещё не запускали, это его первый честный запуск, а не особый режим.
- **Гейт — `session.writable`, токен не участвует.** Импорту не нужна авторизация GitHub (разбор и запись локальны), нужно право правки: в read-only кнопка видна, но неактивна с подсказкой. Сосед «AI промпт» гейтится наоборот (читает GraphQL — нужен токен, пишет ничего — работает в read-only); асимметрия честная.
- **Липкого состояния нет вовсе**: ни текст ответа (он и так лежит в чате/файле), ни галочка пересчёта не переживают закрытие модалки. Новых ключей в `localStorage` не появляется.
- **Тексты — в переводах.** Парсер и границы отдают коды (`AnswerProblemKind`, класс нарушения границы); формулировки для человека живут в i18next на уровне экрана.

## Альтернативы

- **Отдельная сущность «предложение агента» со своим стором и жизненным циклом.** Отвергнута картой (решение 1): второй слой непубликованных изменений со своим путём публикации и конфликтами против черновиков — вместо переиспользования слоя, у которого всё это уже есть.
- **Батч-метод записи в сторе (`importDrafts`).** Цикл `setDraft`/`markDeleted` даёт то же самое; новый метод — вторая точка входа в инварианты стора (история, скоупы), которую пришлось бы держать в синхроне с первой.
- **Переиспользовать/ослабить `isBankFormatFilePath` для границы.** Общая функция на два разных вопроса: «подсветить ли как формат-файл» терпит мягкость, «записать ли черновик по этому пути» — нет; при первой правке под нужды одной стороны ломается другая.
- **Diff-библиотека как несущая конструкция показа (`MergeView`).** Требует вытащить приватные расширения `UnifiedRegexEditor`, дублировать диспатч токенов и гасить accept/reject, противоречащие импорту целиком; на переработанном regex карта правок всё равно не читается — человеку нужен целый старый паттерн рядом с целым новым (#24).
- **Проверять содержимое тел (структура §1, компиляция regex).** Плохое тело безвредно — лежит там, куда человек смотрит, и откатывается; плохой путь пишет туда, куда не смотрит. Компиляция браковала бы корректные для апстрима ответы (`(?i)`), структура не покрывает `senders.txt` и дублирует валидацию редактора (#25).
- **Полная поддержка `<rename>`.** 0 из 4 в корпусе; цена — вид строки на экране плюс доработка `renameDraft` под переименование файла без черновика. Вернётся отдельной фичей, если живые ответы заставят.
- **Терпеть ```-ограждения в парсере.** Вне карты (пп. 7–8): реальный путь съёма — кнопка копирования из чата — их не порождает; корпус подтвердил (0 из 3).
- **Липкая галочка пересчёта (как галочки документов пакета).** У пакета липкость оправдана сценарием «одна формулировка по многим банкам»; здесь это настройка одного прогона — разовое «снял» молча превратилось бы в «навсегда».

## Последствия

- Ответ агента становится **вторым источником черновиков**, и черновик не помнит происхождения: после записи агентская правка неотличима от ручной. Это принятое решение карты (двухшаговая структура «Записать в черновики» → «Опубликовать» вместо гейта «человек посмотрел»), а не упущение.
- Экран импорта — второй потребитель `parseFormatFile` и раскраски `buildPatternHighlightPlan` вне редактора; их контракт становится общим для двух поверхностей.
- `@codemirror/merge` появляется в зависимостях ради одной функции `presentableDiff` (все его зависимости уже в `bun.lock`).
- Каталог поломок проверен только синтетикой — частота в жизни неизвестна; если живые ответы начнут ломаться иначе, перекраивается каталог и, возможно, двухуровневая форма отказа.
- Ветки `prototype/answer-parser` и `prototype/import-screen` остаются образцами до конца имплементации; в `main` их код не едет.
- **Глоссарий.** «Ответ агента» и «Импорт ответа» внесены в `CONTEXT.md` этим же шагом (спека финальная, имплементация — отдельной сессией); «применить ответ» и «предложение агента» помечены как размывающие.
