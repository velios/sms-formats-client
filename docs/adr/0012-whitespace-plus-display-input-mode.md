# Режим `\s+` меняет отображение и ввод, сохраняя regex

Частое `\s+` затрудняет чтение и набор паттерна. В отдельном редакторском режиме оно показывается обычным пробелом, а клавиша пробела вводит `\s+`. Документ CodeMirror хранит канонический regex: переключение не меняет текст, распознавание, сериализация, прогресс и выделение группы работают с прежней строкой.

Сворачивается только пара токенов `\s` и непосредственно следующего жадного `+`. `\s`, `\s*`, `\s{2,}`, `\s+?`, содержимое класса `[\s+]` и экранированный обратный слэш `\\s+` отображаются дословно. Существующий литеральный пробел показывается точкой `·` с предупреждением в обеих раскрасках. Обычный `\s+`-пробел не получает особого декора; в «Группах» он несёт плоский фон группы без белого разрыва, в «Частях» выглядит обычным пробелом.

Свёрнутый `\s+` атомарен: стрелки проходят его одним шагом, Backspace/Delete удаляют целиком. Тонкая правка квантификатора требует обычного режима. Два введённых пробела создают два `\s+`, без автоматического объединения. Для атомарности необходимы команды навигации и удаления CodeMirror; нативного редактирования недостаточно. Подключённая история обеспечивает undo/redo.

Правило ввода охватывает печать, вставку из буфера и сниппеты: литеральные пробелы вне классов преобразуются в `\s+`, внутри `[...]` блокируются. Иначе класс получил бы другое значение. Новые литеральные пробелы в этом режиме появиться не могут; существующие остаются видимыми как `·`. Для пробела или `\s` внутри класса нужен обычный режим.

Тумблер расположен рядом с настройками раскраски, независим от них, выключен по умолчанию и глобально сохраняется в localStorage при смене формата и перезагрузке. В режиме чтения доступно то же отображение, без ввода. На устройстве и в боте этого режима нет.

Хранение отображаемой формы вместо regex отвергнуто, поскольку потребовало бы преобразования у каждого потребителя. Неатомарное сворачивание отвергнуто из-за невидимых позиций каретки и частичного удаления. Поиск подстроки вместо токенов отвергнут из-за ошибок в классах и экранировании. Сворачивание других вариантов `\s` отвергнуто как смешение разной семантики. Ввод `\s` внутри класса отвергнут, поскольку клавиша получила бы два значения. Настройка на каждый формат отвергнута как несогласованная с глобальными настройками отображения. Включение по умолчанию отвергнуто как неожиданное представление чужих паттернов.
