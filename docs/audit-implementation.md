# Реализация аудита от 29 сентября 2026 года

Проект остаётся редактором одного PR и Telegram-ботом с общим ядром распознавания. Изменения устраняют неоднозначность ревизий, параллельные истории документа и старый сценарий создания публикации. Исходное состояние и причины изменений описаны в [аудите](audit-2026-09-29.md), решение о ревизиях и публикации — в [ADR-0018](adr/0018-coherent-revisions-and-publishing.md).

## Итоговая архитектура и разница

| Область | Было | Стало |
| --- | --- | --- |
| Рабочий экран | Страница управляла загрузкой, поиском, правами и публикацией | Страница компонует UI; операции находятся в `features/workspace` |
| Предметная логика | HTTP-клиент и чистые правила находились в `domain/github` | Правила банка и PR — в `domain`, конкретный адаптер — в `infrastructure/github` |
| Удалённые файлы | Отдельный Zustand-кеш, ключ по PR; чтение base могло занять место head | Один React Query-кеш по репозиторию, commit SHA и пути для REST и GraphQL; общий выполняющийся запрос |
| Действующий банк | Несколько загрузчиков; проверки могли получить неполный набор | Общий `loadBankSnapshot`: head с наложением локальных записей и удалений; ошибка загрузки прерывает расчёт |
| Документ | Текст, поля и ошибки синхронизировались через эффекты; CodeMirror имел свою историю | Текст хранится один раз; поля выводятся разбором; undo/redo обоих редакторов и отправителей использует историю документа |
| Исходный файл | Пустая строка также означала отсутствие файла | `headContent: null` означает отсутствие; существующий пустой файл остаётся самостоятельным документом |
| Публикация | Проверялись изменения; свежий SHA подменял проверенный; завершение сбрасывало все черновики | Проверяется весь банк; ожидаемый SHA доходит до атомарной записи; подтверждается только опубликованный набор в исходной области PR; остальные документы получают новый SHA без потери правок |
| Пакет и импорт | Пакет предлагал неподдерживаемый rename; удаления и пересчёт расходились | Переименование выражается `<file>` + `<delete>`; три слоя привязаны к ревизиям; импорт сохраняет историю и передаёт явный снимок в пересчёт |
| Бот | Guest-вызов схлопывал внутренние пробелы; fetch блокировал процесс; ETag мог подтвердить неудачную загрузку | Транспорт сохраняет SMS; сетевой Git асинхронен; незавершённые refs повторяются даже при `304`, последний пригодный корпус сохраняется |
| Список PR | Все дополнительные сведения задерживали список и запрашивались заново | Список отображается сразу; reviews/checks/автор подгружаются с кешем и ограниченной параллельностью; неизвестные проверки показаны явно |
| Сопровождение | Разные версии Bun, deploy без проверок, DOM для всех тестов | Версия из `.bun-version` согласована с Docker и CI; проверки обязательны перед deploy; Node и jsdom разделены |

`features/workspace` выбран вместо нового каталога `application`: существующее разделение возможностей уже подходит для операций рабочей сессии. Базовые классы, универсальный транспорт и отдельный пакет общего движка не понадобились. Zustand остаётся для локальных документов, React Query — для удалённых данных. Существующая история на `travels` сохранена; собственный механизм истории не вводился.

Удалены неиспользуемый `PublishPanel`, publish store и типы, старые GitHub-операции создания форка/ветки/PR, подробное чтение Actions-логов, генератор template-to-regex, разрешающие всё обёртки переключения источника, fingerprint, лишние UI-экспорты и старый кеш тел файлов. Используемый preflight сохранён отдельно. Удалены `regex-simplifier` с переводчиком объяснений и CSS-зависимость `shadcn`; анализ использует собственные токены и JavaScript RegExp.

Большие компоненты разделены по существующим обязанностям: расширения CodeMirror, отображение совпадений, объяснение паттерна, выбор колонок и манифест импорта. Имена описывают PR, исходный head и анализ паттерна. Повествовательные комментарии в производственных TS/TSX убраны; короткие пояснения оставлены для внешней синхронизации редактора, best-effort хранения и специальных ограничений инструментов.

Словари RU/EN дополнены используемыми ключами. Валидация возвращает коды и параметры; формулировки задаёт UI. Диалоги получают доступные имена, меню репозитория и PR использует Radix с клавиатурной навигацией и Escape. Устаревшие требования к инструменту проектирования и ссылки на отсутствующие исходники удалены из инструкций. README и пример конфигурации бота соответствуют действующему процессу.

Сохранённые черновики однократно переводятся в новую модель хранения, чтобы обновление приложения не уничтожило пользовательские правки. Старые неполные снимки рабочей сессии загружаются заново; второго runtime-сценария работы с ними нет.

## Измерения

Сравнение с исходным checkout; производственные TS/TSX/shell без тестов и сгенерированного содержимого:

| Метрика | До | После |
| --- | ---: | ---: |
| Строки производственного кода | 22 220 | 19 566 |
| `BankWorkspace.tsx` | 3 226 | 963 |
| `RegexLab.tsx` | 1 783 | 820 |
| Редактор паттерна | 938 | 362 |
| `ImportAnswerModal.tsx` | 995 | 374 |
| Начальный JS dashboard, gzip | около 384 КБ | 209 КБ |
| JS рабочего экрана по требованию, gzip | входил в начальный файл | 171 КБ |
| Окна пакета / импорта по требованию, gzip | входили в начальный файл | 7,7 / 10,4 КБ |

Суммарное уменьшение кода — 2 654 строк; перенос функций между файлами в эту разницу не засчитывается как удаление. Начальная загрузка dashboard уменьшена примерно на 45%. Первое открытие рабочего экрана требует ещё его чанка и даёт около 380 КБ JS gzip суммарно: экономия достигается главным образом откладыванием загрузки. Предупреждение Vite о чанках свыше 500 КБ остаётся; искусственное дробление и повышение порога не применялись.

## Проверка и границы

- `bun run verify`: typecheck, 489 тестов в 62 файлах, проверка секретов и линтер.
- `bun run build` и `bun run bot:build`: SPA и Linux-бинарник.
- `bun run bot:roundtrip`: семь локальных сценариев webhook с управляемым корпусом, без Telegram и удалённого GitHub.
- Сценарные тесты публикации: межфайловая коллизия, отказ загрузки, изменение документов во время preflight, правки во время записи, смена области PR и ошибка обновления после успешного коммита. Отдельно проверены ожидаемый SHA, независимость base/head в кеше и совместное чтение REST/GraphQL.
- Проверки корпуса используют локальные Git-репозитории и управляемые REST-ответы: повтор main/PR после ошибки fetch, ответы `304`, rebase и сохранение пригодного снимка.
- В Chrome на GitHub-фикстуре проверены сниппеты, структурный и текстовый редакторы, общая история, некорректный исходный документ, отправители, создание/переименование/удаление локального файла, запрет конфликтующего пути, клавиатурное меню, оба режима поиска, переключение RU/EN, валидация, открытие диалога публикации, скачивание пакета и импорт с удалением и пересчётом. Ошибок и предупреждений приложения в консоли не обнаружено.

Реальная запись пользовательских форматов в GitHub, отправка Telegram и продуктивный deploy не выполнялись. Их границы проверены управляемыми сценариями; CI повторяет проверки и сборки PR. Движок остаётся JavaScript RegExp: полная эквивалентность Python-валидатору и мобильным движкам не заявляется.
