# Regex банковских SMS

Правила написания и исправления паттернов. Паттерны и триггеры — в §2 и каталоге `regex-snippets.toml`. При правке regex следуй этому справочнику: существующие паттерны банка могут использовать устаревшие соглашения.

## 1. Исполнение

Цель — корректное распознавание SMS в мобильном приложении Zenmoney. Редактор помогает править форматы и проверяет их браузерным RegExp; GitHub Actions репозитория — Python `re`. Эти проверки приближают поведение приложения; полная совместимость движков не гарантируется.

Поиск подстрочный. Редактор и Python CI перед распознаванием схлопывают серии переводов строк SMS в пробел, срезают края и применяют NFC к рабочей копии; хранимый EXAMPLE сохраняется дословно. regex101 получает рабочую копию. EXAMPLE не меняют ни пользователь, ни агент, независимо от указаний задачи.

Без флагов регистр значим; `/pattern/flags` поддерживает `i,u,m,s`, начальный `(?i)` поддержан редактором. В Python `\w`, `\W`, `\d`, `\b` опираются на Unicode, в браузере — на ASCII, даже с флагом `u`; Unicode-регистр тоже различается. Например, Python распознаёт кириллицу через `\w` и `[a-z]` с `(?i)` может распознать `İ`; браузер — нет. Для общего поведения используй реальные литералы или явные классы вместо границ/классов, зависящих от Unicode.

Capture-группа после срезки краёв должна равняться значению сущности в NFC-копии; у денежных значений игнорируются все пробелы. Пунктуация и соседние токены в группу не входят. Порядок групп соответствует порядку сущностей в SMS и строке COLUMNS.

## 2. Сниппеты

У каждой сущности один дефолт; у служебной склейки — дефолт на роль. Эта таблица позволяет работать и без TOML; полный каталог содержит примеры и пояснения.

| Группа | Вид | Паттерн | Условие |

| amount | альтернатива | `(\d[\d\s.,]*(?:[.,]\d{2})?)` | Нужна точная десятичная граница; копейки присутствуют не всегда. |
| balance | дефолт | `(-?\d[\d\s.,]*)` | Дефолт баланса: целые числа, разный разделитель/точность; минус внутри группы. |

## 3. Сущности

У сущности один дефолт. Вставляй его дословно, без сужения под единственный пример. Альтернатива нужна только при подтверждённом EXAMPLE триггере; между подходящими альтернативами выбирай более конкретную. Частота формы в корпусе не является триггером. При исправлении недефолтную форму без триггера заменяй дефолтом в пределах области задачи.

| Сущность | Правило |
| --- | --- |
| `income`, `outcome`, `fee`, `cashback`, `op_income`, `op_outcome` | Число начинается с цифры. Знак, задающий направление, оставляй вне группы. Обязательные копейки/точная правая граница и опциональные копейки — разные триггеры каталога. |
| `balance`, `av_balance` | Минус входит в группу. При соседнем времени нужна точная граница, иначе `9141.03 15:43` утечёт в баланс. |
| `instrument`, `acc_instrument`, `op_instrument` | Дефолт — непробельный токен. Сам ISO-код не требует альтернативы; она нужна, если дефолт захватил бы лишнее. При дубликате `kr SEK balance:` захвати только `kr`, дубликат пропусти склейкой до `balance:`. |
| `syncid`, `syncid#cash` | Только наша карта/счёт; максимум один id в SMS. Карта контрагента не id. Для наличных — `syncid#cash`. Маску оставляй вне захвата; альтернативы длины — по каталогу. |
| `date#…` | Дата операции, без времени; дата срока/расписания/следующего списания не подходит. Суффикс задаёт порядок (`dMy`, `yMd`, `Mdy`, `dM`, `Md`), а не длину года/разделитель. Формат-строки `date#dd.MM.yyyy` — легаси. |
| `payee` | Контрагент прихода или расхода; банк-посредник/канал не подходит. Нежадный захват ограничивай реальным правым разделителем, иначе он заберёт соседнюю сущность. |
| `comment` | Переменный пользовательский текст или отдельное поле сообщения. Фиксированное название операции («Оплата», «Перевод») — якорь, не комментарий. |
| `mcc` | Целое число по реальному маркеру MCC. |

Направление определяется смыслом операции и знаком: зачисление/пополнение/credited и `+` — приход; покупка/списание/снятие/debited — расход. Знак суммы операции оставляй вне capture, если значение без знака.

## 4. Склейка и якоря

Между токенами используй `\s+`, между надёжными якорями — `.*?`; жадная `.*` допустима перед надёжным якорем. `\s*` и опциональные конструкции допускай только при EXAMPLE с токеном/пробелом и без него. Это ограничение относится к авторской склейке; дефолтные сниппеты вставляй как есть.

Якорь — реально присутствующий стабильный текст в NFC-копии SMS с её регистром. Для наблюдаемого различия регистра можно `[Nn]aqd`. Авторские классы/кванторы расширяй только под наблюдаемую вариацию; сохраняй форму токена. Значения валют, сумм, карт и мерчантов извлекай группами, не фиксируй литералами. Смешанные валютные альтернативы вроде `(?:[A-Z]{3}|[₽р])` — тоже хардкод. Переменный URL-путь/параметры, id сессии и номер операции не подходят для якоря: используй стабильный префикс или закончи паттерн раньше.

Транзакционные паттерны пишутся без ведущего `^`, концевого `$` и ведущего/хвостового `.*`: поиск уже подстрочный. Информационные форматы с пустыми COLUMNS используют собственный классификаторный стиль, например `^anchor.*`. Нужный разделитель поля (например конец комментария) может быть локальной границей.

## 5. Слияние и разведение

Новый формат сначала примерь к существующим. Сливай одинаковые шаблоны с одинаковым истинным набором сущностей; отдельный файл нужен, когда слияние существенно усложняет regex. Старые COLUMNS могут ошибаться: заново выдели сущности обоих EXAMPLE перед решением. При слиянии все исходные примеры сохраняются дословно.

Сущность то присутствует, то отсутствует — это разные форматы, без необязательной capture-группы. Разводи их негативным lookahead по уникальному реальному маркеру чужого варианта с точным регистром и разделителем, например `Dostupno:`. Lookahead не добавляет групп.

- В начале: `(?!.*Dostupno:)…` проверяет текст от начала матча. Выбирай при ненадёжной локальной привязке.
- Локально: `…([^.]+)\.(?!\s*Dostupno:)`. Захват перед проверкой не должен пересекать границу блока: `(.*?)` расширится при откате и обойдёт запрет.

Маркер перед началом матча передний lookahead не видит. Если наборы сущностей совпадают, метка канала в разных позициях — повод для слияния. Lookbehind в Python должен иметь фиксированную ширину: `(?<!СБП:\s)` не выдержит два пробела.

## 6. Проверка

Собери итоговый банк и проверь все форматы, включая информационные и неизменённые: каждый EXAMPLE распознаётся своим regex и никаким чужим; capture-группы соответствуют COLUMNS по числу, порядку и смыслу. Исходные уникальные EXAMPLE сохранены посимвольно. Непроверенные условия назови явно; отличие браузера от Python не устраняй изменением примера.
