# Прототип экрана импорта (#27)

Не продакшн-код. Задача — дать на что реагировать при решении шести вопросов
тикета [#27](https://github.com/velios/sms-formats-client/issues/27), а не
уехать в приложение. Реализатор пишет модуль заново по PRD + ADR.

## Как смотреть

```bash
cp .env.example .env   # если .env ещё нет
bun run dev
```

Открыть `http://localhost:5173/prototype/import-screen`.

- `?variant=A|B|C` — компоновка экрана, переключается стрелками ←/→ и панелью
  в правом нижнем углу;
- `?case=<id>` — случай из корпуса, кнопки в той же панели.

## Варианты

| | ставка |
|---|---|
| **A — Мастер** | три шага (вставка → разбор → итог), проза свёрнута, «было → стало» по клику аккордеоном, предупреждение о перезаписи полосой над кнопкой, итог отдельным экраном |
| **B — Две панели** | один экран, слева список, справа детали; проза — первая строка списка наравне с файлами; предупреждение — метка в строке; итог показывается в правой панели |
| **C — Лента** | всё раскрыто сразу, одна прокрутка; проза первой и целиком; предупреждение — карточка на своём месте среди файлов; после импорта модалка закрывается, итог уезжает тостом |

Общее у всех трёх — показ «было → стало» (`StructuralDiff.tsx`): он задан
резолюцией [#24](https://github.com/velios/sms-formats-client/issues/24) и
предметом спора не является.

## Случаи

Первые три — настоящий корпус [#23](https://github.com/velios/sms-formats-client/issues/23),
«было» вынуто из тех же пакетов промта (`fixtures/before.json`). Три последних
сконструированы: корпус их не дал.

| id | что проверяет |
|---|---|
| `sber` | плотность: 10 изменённых + 4 удалённых, длинная проза, один файл с ручной правкой |
| `centercredit` | senders.txt как отдельная форма показа; в прозе два отказа агента |
| `amex` | ни одного блока — «импортировать нечего», не ошибка |
| `broken` | обрыв на 95-й строке → отказ на весь ответ (#26) |
| `out-of-bounds` | README и чужой банк → отказ целиком (#25) |
| `edge` | новый файл, `<rename>`, дубль пути — импорт не рушат (#26) |

`parse-answer.ts` — копия прототипа парсера с ветки `prototype/answer-parser`,
дословно, под `@ts-nocheck` (строгий `noUncheckedIndexedAccess` из `src/` на
неё не рассчитывался).
