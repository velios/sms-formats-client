# Прототип экрана импорта (#27)

Не продакшн-код. Задача — дать на что реагировать при решении шести вопросов
тикета [#27](https://github.com/velios/sms-formats-client/issues/27), а не
уехать в приложение. Реализатор пишет модуль заново по PRD + ADR.

## Как смотреть

```bash
cp .env.example .env   # если .env ещё нет
bun run dev
```

Открыть `http://localhost:5173/prototype/import-screen`.

- `?variant=A|B|C` — компоновка экрана, переключается стрелками ←/→ и панелью
  в правом нижнем углу;
- `?case=<id>` — случай из корпуса, кнопки в той же панели.

## Варианты

| | ставка |
|---|---|
| **A — Мастер** | три шага (вставка → разбор → итог), проза свёрнута, «было → стало» по клику аккордеоном, предупреждение о перезаписи полосой над кнопкой, итог отдельным экраном |
| **B — Две панели** | один экран, слева список, справа детали; проза — первая строка списка наравне с файлами; предупреждение — метка в строке; итог показывается в правой панели |
| **C — Лента** | всё раскрыто сразу, одна прокрутка; проза первой и целиком; предупреждение — карточка на своём месте среди файлов; после импорта модалка закрывается, итог уезжает тостом |
| **D — B + корзина и номер** | B с двумя правками: удаление несёт два признака (красная точка **и** значок корзины, в том же слоте, где карандаш у перезаписи ручной правки); имя обрезается посередине, так что хвост `_11792.txt` виден всегда |

D доведён до вида, который можно брать в продакшн почти как есть; A, B и C
остались черновыми — они первоисточник спора про компоновку, а не про отделку.

### Что вскрыл D

Правило «есть номер → файл существует» держится только в одну сторону.
Номер присваивает апстрим при публикации, поэтому файл, заведённый в текущем
PR, существует, но номера не имеет: в случае `sber` из 10 изменённых файлов
номер есть у трёх. Поэтому «новый» в D опознаётся не отсутствием номера, а
зелёной точкой и значком «файл с плюсом»; номер отвечает на другой вопрос —
«этот формат уже опубликован в апстриме».

Эти два вопроса разведены по разным слотам и не спорят: жёлоб слева говорит,
**что произойдёт** (изменён / новый / удалён / без изменений), хвост имени —
**опубликован ли формат в апстриме**. Чего в списке видно быть не может — это
разницы между «файла ещё нет» и «файл заведён в этом PR, номера ещё нет»: обе
формы выглядят как имя без номера. Ответ на это даётся словами в правой
панели, строкой `provenanceText`.

Общее у всех вариантов — показ «было → стало» (`StructuralDiff.tsx`): он задан
резолюцией [#24](https://github.com/velios/sms-formats-client/issues/24) и
предметом спора не является.

### Отделка D: что сделано

- **Палитра из токенов.** Было — палитра тёмной темы GitHub (`#f85149`,
  `#3fb950`, `#d29922`) поверх светлой темы приложения. Стало — токены, причём
  те же, которыми список файлов банка (`BankWorkspace.tsx:1259`) уже метит свои
  строки: `--c-accent` «изменён», `--c-success` «новый». `--c-warning` потрачен
  ровно на один смысл — «что-то потеряется»; `--c-error` — «необратимо или
  нельзя». Заодно поправлены `KIND_COLOR` и `StructuralDiff` — там та же
  палитра, а она не была предметом спора вариантов.
- **Жёлоб.** Точка геометрическая, а не глиф `•`; ширина слота постоянная; та
  же метка поднимается в шапку правой панели у выбранной строки. Удаление
  зачёркивается — как в списке файлов банка; это единственный признак,
  переживающий дальтонизм (красная и зелёная точки рядом различимы не всем).
- **Строка разбора не врёт.** Было «Ответ разобран» над неразобранным ответом и
  счётчики над отказом. Стало — своя формулировка на каждое состояние, а
  счётчики заодно работают легендой жёлоба.
- **Ничего не теряется молча.** Выброшенный `<rename>` и дубль пути показаны
  отдельной заметкой; перекрытая строка дубля подписана «перекрыт ниже»; файл
  за границей банка помечен запретом, а не «новым».
- **Отказ говорит, что делать** — и даёт кнопку «Вставить заново».
- **Клавиатура и фокус.** Список — listbox с ролями, стрелками и кольцом
  фокуса; при открытии фокус встаёт на выбранную строку, а не на первую
  попавшуюся кнопку (для этого `ModalDialog` научился принимать
  `onOpenAutoFocus`).
- **Числа склоняются**, проза читается по мере ~68 знаков.

### Отделка D: что осталось

- **Пословная подсветка в regex-строке** (`markWords`) — по-прежнему заглушка
  вместо `presentableDiff`: красит крупными кусками, на длинных выражениях
  подсвечивает почти всю строку. По #24 это украшение; чинится вместе с
  `presentableDiff`.
- **Строки не в i18n**: прототип пишет по-русски напрямую, продакшн-модуль
  берёт их через `react-i18next`.
- **Предупреждение radix `DialogContent requires a DialogTitle`** — не ложное:
  `ModalDialog` передаёт заголовку свой `id`, и radix не находит собственный.
  Чинится в `ModalDialog`, касается всех модалок приложения.

## Случаи

Первые три — настоящий корпус [#23](https://github.com/velios/sms-formats-client/issues/23),
«было» вынуто из тех же пакетов промта (`fixtures/before.json`). Три последних
сконструированы: корпус их не дал.

| id | что проверяет |
|---|---|
| `sber` | плотность: 10 изменённых + 4 удалённых, длинная проза, один файл с ручной правкой |
| `centercredit` | senders.txt как отдельная форма показа; в прозе два отказа агента |
| `amex` | ни одного блока — «импортировать нечего», не ошибка |
| `broken` | обрыв на 95-й строке → отказ на весь ответ (#26) |
| `out-of-bounds` | README и чужой банк → отказ целиком (#25) |
| `edge` | новый файл, `<rename>`, дубль пути — импорт не рушат (#26) |

`parse-answer.ts` — копия прототипа парсера с ветки `prototype/answer-parser`,
дословно, под `@ts-nocheck` (строгий `noUncheckedIndexedAccess` из `src/` на
неё не рассчитывался).
