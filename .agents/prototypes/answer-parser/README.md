# Прототип парсера ответа агента

Тикет [#26 «Парсер ответа: что разбираем, где отказываем»](https://github.com/velios/sms-formats-client/issues/26),
карта [#22](https://github.com/velios/sms-formats-client/issues/22).

**Это не продакшн-код.** Задача прототипа — дать факты на реальном корпусе и
зафиксировать пять решений, которые нельзя было принять на бумаге. Реализатор
пишет модуль заново по ADR; отсюда переезжают решения, а не файлы.

## Что где

| файл | что это |
|---|---|
| `parse-answer.ts` | чистая функция `parseAnswer(text)` — весь предмет обсуждения |
| `parse-answer.test.ts` | 18 тестов: 5 на реальном корпусе, остальные — ловушки и поломки |
| `report.ts` | прогон по корпусу, печатает что разобралось |

Корпус лежит в `.agents/research-corpus/` (копия собранного в
[#23](https://github.com/velios/sms-formats-client/issues/23); папка `.agents/`
гитигнорится, в ветку прототипа корпус не попадает).

## Запуск

```sh
bun test ./.agents/prototypes/answer-parser/parse-answer.test.ts
bun .agents/prototypes/answer-parser/report.ts
```

## Принятые решения

1. **Грамматика построчная** — зеркало сборки пакета (`src/features/prompt-package/core.ts:109`),
   где блок печатается как `<tag …>\n${body}\n</tag>` без экранирования. Открывающий
   и закрывающий теги — строки целиком; всё между ними — тело дословно. Отсюда
   `<` и `>` внутри regex тегами быть не могут в принципе.
2. **`<rename>` узнаём, но отказываем.** В корпусе 0 из 4; поддержка стоит
   отдельного вида строки на экране импорта и доработки `renameDraft`
   (`src/store/index.ts:374` выходит, если черновика по старому пути ещё нет).
   Не узнавать нельзя — блок утёк бы в прозу и изменение потерялось молча.
3. **Два уровня отказа.** «Блок не доехал» (`unclosed`, `orphan-close`,
   `malformed-open`, `empty-path`) → отказ на весь ответ. «Блок доехал, но с ним
   что-то не так» (`duplicate-path`, `conflicting-path`, `unsupported-rename`) →
   импорт доступен, проблемы показаны рядом.
4. **Результат — размеченное объединение** `broken` | `parsed`: у сломанного
   ответа поля `changes` нет физически.
5. **Порядок ответа = порядок применения**, побеждает последний блок по пути.

## Чего прототип не проверил

Корпус **не содержит ни одной поломки** — ни обрыва, ни незакрытого тега, ни
дубля пути. Каталог поломок сконструирован и проверен синтетикой; частота их в
жизни неизвестна.
